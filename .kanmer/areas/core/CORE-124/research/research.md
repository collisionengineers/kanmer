# Research — CORE-124: deliberate batch workspaces on renewable leases

## Question

How does FRD-030 batch mode (AC4: three small related tickets complete in one frozen batch workspace with one PR/head attestation and member-specific verification evidence; AC5: an unrelated ticket cannot join a started batch or share its workspace) land on the CORE-115 lease contract merged at origin/main 3dd48d37 — as one bounded PR, additive to the v0.3.12-served board, without a new MCP tool, without regressing CORE-115's accepted-risk list (F-004..F-016) and without widening the unlocked-writer window CORE-125 owns?

## Findings

- **The extension point CORE-115 left is exactly `assertWorkspaceFree`.** `packages/core/src/store.ts:1114-1130` scans every non-archived taken ticket and refuses `WORKSPACE_OCCUPIED` when the worktree (normalised) or branch (exact) matches; its doc comment says "batch membership (CORE-124) is the only planned exception". It runs inside `withLeaseLock` (`store.ts:1095`, `.kanmer/leases.lock`) from `takeTicket` (`:1196`), after the `LEASE_LIVE` check and before any write, and `force` never bypasses it. Everything batch mode needs to decide is available inside that lock: the sibling list, each sibling's `lease_*`/`taken_at`/`status`/`archived`.
- **Unknown frontmatter keys are passthrough and ordered.** `ItemFrontmatterSchema` is `.passthrough()` (`types.ts`), `KEY_ORDER` (`frontmatter.ts:5-40`) places the nine `lease_*` keys after `remediation_budget`. CORE-115's report confirms the installed v0.3.12 server lists tickets carrying `lease_*` fields. New optional `lease_batch` / `lease_batch_frozen_at` fields on members are therefore safe: no format bump, no `migrate_board` step. A `.kanmer/batches/<id>.md` record would instead add a directory the v0.3.12 `listItems` (`store.ts:552-607` reads `areas/` only) and doctor never expected, and would need its own lock/CAS — the on-member field is the cheaper, already-proven shape. Membership = the set of non-archived tickets sharing one `lease_batch` id; the record has no second copy to drift from.
- **Membership cannot be edited through generic writers.** `UpdateItemPatch` (`types.ts`) has no lease fields and `update_item` (`index.ts:1353`) exposes none, so the only way a batch field can be written is a lease verb under the lease lock. That is what keeps "a ticket cannot join a started batch" enforceable and keeps this ticket inside the CORE-125 boundary: no new unlocked writer is introduced (the CORE-125 gap — `updateItem`/`moveItem` racing lease writes — is unchanged, neither widened nor solved).
- **`take_ticket` is the right surface, no new tool.** Roster is 39 (`smoke.mjs:69`, `plugin:check`). `take_ticket` already carries lease params (`index.ts:1450-1520`) and the handler passes them straight to `store.takeTicket`; two optional params — `batch` (id) and `batch_members` (ids) — extend the same tool. `errors.ts:8` classifies `LEASE_CONFLICT` from stable prefixes, so new `BATCH_*:` prefixes need one array entry each to surface as `LEASE_CONFLICT` (a `Conflict:` prefix would instead be `REVISION_CONFLICT`, which is wrong here).
- **Freeze at first take is one write set inside the lock.** `takeTicket` re-reads the ticket inside `withLeaseLock`; the batch declaration (`batch_members`) can validate every named member (exists, ticket, not archived, not terminal, not taken, not already in another batch) and stamp `lease_batch` + `lease_batch_frozen_at` on each member file in the same critical section before minting the taker's lease. Later member takes (same `lease_batch`, workspace equal to the batch workspace) pass the occupancy check; a member trying a different worktree/branch violates "one workspace per batch / one workspace per ticket" and is refused; a non-member on the batch workspace still gets `WORKSPACE_OCCUPIED` (AC5 second half); a `batch_members` list naming a ticket that already belongs to a frozen batch is refused (AC5 first half).
- **Terminal is definable from existing fields.** `reconciliation.ts:141` treats Done as the terminal claim shape, and kanmer-closeout accepts two terminal shapes: status Done (not archived) or retired non-success (status Verifying, archived). So `terminal = status === "done" || archived === true`. `releaseTicket` (`store.ts:1244-1266`, the closeout verb, also the GUI path) runs inside the lease lock and can refuse while any *other* member is non-terminal; when the last member releases, the batch fields clear with the rest of the lease record. `release` currently ignores lease ids (F-010, accepted) — unchanged here.
- **Per-member review mapping and proof already exist per ticket.** `scratch/review.md` attestation (`review-attestation.ts`: `pr`, `head_sha`, `verdict`, …) and `proof/proof.md` are ticket documents; the enter-review/enter-done gates are per ticket (`get_doc_gates`). AC4 needs no new document type: three members each write an attestation naming the same `pr`/`head_sha` and their own proof. A store read helper (`batchState`) that reports members, their statuses and terminal-ness gives the packet and closeout one view; the packet's `claim` block (`execution-packet.ts:66-84, 515-530`) is where a worker learns it is in a batch and which siblings share its workspace.
- **Packet occupancy checks are physical and stay.** `get_execution_packet` refuses another ticket's recorded worktree (`execution-packet.ts:254-362`); for a batch member, the "another active ticket's worktree" refusal must except same-batch siblings, otherwise a second member can never get a packet on the shared worktree. This is the one MCP-side rule change besides the take params.
- **Skills.** `kanmer-execute/SKILL.md:184-201` (fresh worktree creation and `take_ticket`), `kanmer-closeout/SKILL.md` §2 git half and §3 release, `kanmer-auto/SKILL.md:95` ("Each lane uses its own `.worktrees/<id>` worktree and branch"). `scripts/verify-skill-prose.mjs` pins regexes on execute (`:488-503`: resumed/fresh lanes, `list_items` sweep) and closeout (`:460-480`: retired shape sentences) — additions must be new sentences, not rewrites of pinned ones. Check 4 requires every doc type named in skills to exist in `profiles.ts`; batch prose must not coin a doc type.
- **Tests and smoke.** `claims.test.ts:367-560` is the lease suite (`ageClaim`, `stripLease`, `setBoardLine` helpers, byte-identical-file assertions on refusal); `smoke.mjs:2180-2260` is the MCP lease fixture (`claimId` on `.worktrees/claim`, `otherClaimId` contender). AC4/AC5 fixtures fit both rails. `store.test.ts:685` asserts the exact activity op sequence for take/release — batch stamping must not add ops to the *taker's* sequence beyond what that test pins (stamp sibling files without extra activity entries, as CORE-115 did for lease minting).
- **Docs.** `tool-reference.md:47` (`take_ticket` row) and `:127-136` (lease fields), AGENTS.md §4 field example (`:373-380`) and §8 gotcha 17; `docs/manual/glossary.md` "Lease" entry feeds `chapters.generated.ts` (`build:manual`, required by `verify:docs`). F-016 (take_ticket description omits branch-mismatch) can be fixed in the same description edit.
- Governing constraints: FRD-030 batch paragraph + AC4/AC5; HZN-008 context ("workspace: one active writer's isolated or frozen explicit batch worktree/branch", additive only, no mandatory batch mode, no silent deletion). No project-declared source (`get_sources` → `declaredCount: 0`).

## Implications

- **Record:** two additive optional frontmatter keys on every member — `lease_batch` (batch id, caller-supplied, e.g. `batch-core-12x`) and `lease_batch_frozen_at` (timestamp of the first member take). No new folder, no format bump.
- **Declare + freeze:** `take_ticket … batch: "<id>", batch_members: [self, …]` on the first take stamps and freezes membership (≥ 2 members, all valid) and takes the caller's ticket on the batch workspace. `batch_members` on an already-frozen batch → `BATCH_FROZEN`.
- **Join workspace:** a later `take_ticket` of a member (with `batch` matching its `lease_batch`, or inferred from it) on the batch's recorded worktree/branch passes `assertWorkspaceFree`; any other worktree/branch → `BATCH_WORKSPACE_MISMATCH`; a non-member → `WORKSPACE_OCCUPIED` (message now names the batch).
- **Shared evidence, per-member proof:** unchanged documents; packet `claim.batch` lists members so the worker knows the PR is shared; test asserts three attestations on one head + three proofs.
- **Cleanup waits:** `releaseTicket` refuses `BATCH_ACTIVE` while another member is non-terminal; `batchState(id)` is the read used by the packet and by closeout prose ("closeout refuses worktree removal while any member is non-terminal").
- **Surfaces:** `take_ticket` two params, packet `claim.batch`, `errors.ts` prefixes, tool-reference, AGENTS §4/§8, glossary, execute/closeout/auto sentences, bundle rebuild. Roster stays 39.
