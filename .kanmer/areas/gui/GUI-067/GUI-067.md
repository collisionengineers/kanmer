## What

There is no root `typecheck` script at all. Add one that covers **every**
workspace, so a green rail means what it says.

## Why

During [[GUI-064]] I ran the documented rail, got green, and reported
"typecheck clean" on the PR. It was not: four `McpSessions` object literals in
`apps/gui/src/renderer/src/lib/update.test.ts` were missing a newly required
field. The error only surfaced later, when `release.mjs` ran
`npm run typecheck -w @kanmer/gui` directly — **after** the PR had been merged.
Fixed in `c8b94a4`.

Two gaps lined up:

- there is **no root `typecheck` script**, so AGENTS.md §10 named a
  *per-workspace* command and a contributor following the checklist type-checked
  one workspace of four; and
- **vitest does not typecheck**, so a full green test run says nothing about
  types in test files.

Test files are exactly where this bites: they construct shared types by hand, so
they break first when a type gains a field, and they are the least likely place
anyone re-checks.

AGENTS.md §10 is the verification checklist people follow before calling
something done. If the commands it names do not cover the repo, the checklist
launders a false claim — which is what happened here.

## Approach

- Add a root aggregate over all workspaces, using `--workspaces --if-present` so
  a workspace added later is covered without anyone remembering.
- Swap the per-workspace form for it in AGENTS.md §6, §10 and the release rail.

- [x] `npm run typecheck` clean on merged main.

## Outcome

Shipped as PR [#36](https://github.com/collisionengineers/kanmer/pull/36), merge
commit `5d0e0d7`. Three files, +8 −3.

**The ticket's premise was wrong, and the truth was worse.** It assumed a root
`typecheck` existed and missed the GUI; there was none at all
(`scripts.typecheck` → `undefined`). So §10 named `-w @kanmer/gui`, and the
checklist read as if it covered the repo while covering a quarter of it.

Its second claim needed no fix and got none: `apps/gui/tsconfig.web.json` already
includes `src/renderer/**/*`, so the GUI's own config covers test files. That was
never the gap.

**The release rail had the same bug.** `release.mjs` was the only thing running
any typecheck, and it ran one workspace's — so `c8b94a4` had two chances to be
caught and missed both. Now `npm run typecheck`.

**The ordering mattered and cost a pause.** [[GUI-078]] had to land first:
`@kanmer/ui` had a typecheck script nothing had ever run, and the first honest
aggregate turned the rail red with 12 errors that were themselves masking 12
absent `ProjectClient` methods. Excluding the workspace to get green would have
reproduced this ticket's own defect. It was paused, the blocker filed, and it
resumed.

**Known residual, recorded in `proof` rather than left implicit:**
`--if-present` skips a workspace with **no** `typecheck` script silently, so the
"four names in the output" check is a human step, not a mechanical one. Asserting
the workspace list belongs with [[CORE-025]].
