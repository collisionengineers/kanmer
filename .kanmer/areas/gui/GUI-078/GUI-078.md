## What

`packages/ui/src/demo.tsx` does not typecheck — **12 errors**, all of them the
v2 core API. Bring it up to format 3.

## Why

`@kanmer/ui` is the design system packaged for Claude Design. It has a
`typecheck` script and **nothing has ever run it**: `build:ui` exists, no rail
calls it, and tsup does not typecheck. So the errors have been there since
format 3 landed, invisible.

Found by [[GUI-067]], which adds a root aggregate typecheck and cannot ship
while a workspace it covers is red.

`demo.tsx` is not scaffolding that could be excluded — `index.ts:75-79` exports
`demoBoard`, `demoItems`, `demoActivity` and `KanmerProviderProps` from it. It is
part of the package's public surface, so a consumer importing the demo provider
gets types that do not match the core it is demonstrating.

## Approach

- Fix the shapes against `packages/core/src/types.ts`, not against what makes the
  compiler quiet. A cast to `any` here would ship wrong types to a design-system
  consumer, which is worse than the current state.
- Replace the seven-stage vocabulary with the six fixed stages, and drop the fake
  gate logic rather than porting it.
- Check the rest of `packages/ui/src` while here.
- Verify the demo still *runs*, not merely compiles.

## Verification

## Outcome

Shipped as PR [#35](https://github.com/collisionengineers/kanmer/pull/35), merge
commit `c6a48b2`. Two files, +276 −65.

**The scope estimate was wrong by roughly double, and the reason is worth
keeping.** This was filed as "12 errors, mechanical". Fixing them revealed a
thirteenth the others had been masking: the demo was missing **twelve
`ProjectClient` methods** — groups, references, `getGates`, `dispatchOptions`,
the whole v3 surface. TypeScript reports property-level mismatches inside an
object literal *before* it reports the literal being structurally incomplete, so
none of it was visible while the shape errors stood. **An error count is not a
size estimate.**

They were implemented as working in-memory fakes rather than throwing stubs, with
two demo groups whose membership lives **on the tickets** and is derived on read
— the model FRD-001 actually specifies.

**Two things the compiler could not see** were fixed with them: `getFormat`
returned `2` (a permanent migration banner for any consumer), and `getGateStatus`
hardcoded `"plan.md required before leaving Planning"` against a stage format 3
does not have. The latter is now an empty map — the demo should not be a second
gate engine.

**I shipped the opposite of my own plan.** The plan and `open-questions` both
argued to import `DEFAULT_PROFILES` and the stage list from `@kanmer/core` rather
than retype them. It typechecked, then the build failed: core declares one export
whose barrel reaches `node:fs`, `node:path` and `node:crypto`, and this package
builds `platform: "browser"`. Types erase at compile time; values do not — which
is why the original imports were type-only, a constraint written down nowhere.
The constants are now mirrored in one block, each naming its source, with a
comment saying they will drift.

**Follow-up:** [[CORE-027]] — a browser-safe subpath export for core, plus a rail
check that the emitted browser entry references no `node:` specifier. It names
[[SKILL-013]] as the change that will desynchronise this copy, so the debt has a
date rather than being open-ended.

**Unblocks [[GUI-067]]**: all four workspaces now typecheck clean.
