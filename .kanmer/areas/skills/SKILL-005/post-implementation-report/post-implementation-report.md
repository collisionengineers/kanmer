## Against the governing docs

**ADR-0009 layer 3** — the block orients, it does not gate. That is why the
document pipeline came out: describing requirements the server owns is what let
this text go stale within one release. It now points at `get_doc_gates` instead
of restating anything.

**FRD-012 R3** — setup installs the block; unchanged mechanically.

## The substantive change

The block no longer describes a document pipeline. There isn't one — there are
five profiles, and which applies is per ticket. Stating a single pipeline does
not merely misinform; it teaches an agent to write six documents for a two-line
fix, which is PRD-001 problem 1.

## Nearly lost something

Regenerating `AGENTS.md` revealed the previous block carried board-worktree
guidance — never create, switch or push the board branch yourself — that a
generic body dropped. It is general to any Git project set up through the GUI,
not local to this repo, so it is now in the canonical body. Without running the
script against a real file I would have shipped the deletion.

## For review

**The block is longer than the old one** (a five-line opening paragraph plus
nine bullets, against four plus nine). Every agent reads it every session, so
length is a real cost. I judged the profile explanation and the board-worktree
warning worth it — both are things an agent gets wrong expensively — but it is a
judgement call and a reviewer may disagree with the opening paragraph's length.

**Skills are listed by name, which will go stale again.** The roster line has
now been wrong twice. A pointer ("call `list_skills`") would be self-maintaining,
but no such tool exists, and inventing one is not this ticket.
