## Problem

[[GUI-152]] (0.4.2) ships the Focus Board scopes, sidebar and bounded columns. The approved reference (`Kanmer_Upgrade_Pack_2026-09-05/approved-ui/01-focus-board.html`) also has a Board/List toggle with a table view and pinning, and the implementation contract (pack file 09 §5) lists parity rows that turned out to be **new scope**, not preservation: the GUI's `moveItem` IPC carries no `expectedRevision` so a stale write cannot show a conflict, and `stageEntered` is first-entry only so "time in stage" cannot be derived truthfully today.

## Outcome

Board/List toggle with the same filtered data and selection semantics; Pinned scope; `expectedRevision` on GUI moves and edits with a visible conflict that preserves unsaved local input; keyboard-only stage move with the same gate refusal as pointer moves; either an authoritative current-visit stage timestamp (explicit field + migration) or the metric omitted; qualification against the desktop/laptop/mobile previews on a disposable board and in the packaged renderer.

## Acceptance

- List and board views share one selector pipeline (no second implementation of acceptance logic); sortable columns and a pager.
- Unsaved detail edits plus an external ticket update: local input preserved, conflict exposed, no lost write (pack AT-35).
- Keyboard-only stage move gets the same permissions/validation as pointer (AT-36).
- Time-in-stage either reflects the current visit from an authoritative record or is not shown; no precise misleading ages.
- Parity checklist over every existing settings section (Board, Profiles, Appearance, Git, Connect, Dispatch, Remote access, OpenAI tunnel, Projects), standup, activity, claims/leases/dispatch controls, archived restore, multi-project tabs — checked before any old shell code is removed.
- Packaged renderer qualification recorded separately from prototype validation; the desktop runtime itself is R2-DESKTOP.

## Out of scope

Electron runtime upgrade; replacing the six-stage workflow; a single-parent epic model; prototype fixture data in production.

## Technical seam

`apps/gui/src/shared/ipc.ts` `moveItem`/`updateItem` (+ `expectedRevision` from core `assertRevision`), `App.tsx` `onMove`, `Editor.tsx`, new `ListView.tsx`, `lib/scopes.ts`/`lib/paging.ts` from GUI-152, `packages/core/src/types.ts` `stageEntered` (or a new current-visit field with `migrate.ts` step).
