# Plan — MCP-043: Refresh committed MCP plugin artifact after remote-access changes

## Approach

Start from a clean worktree at origin/main, run the repository's canonical npm run plugin:build path, and retain only the generated plugin bundle diff. This is preferable to hand-editing or altering parity scripts because the artifact is a deterministic derivative and MCP-028/MCP-042 explicitly define generated-byte refreshes as the remediation.

## Governing docs

- ADR-0016 — compiled workflow: the generated bundle is derived from the reviewed source tree; the branch records the exact build and commit, and no hand-authored generated bytes are introduced.
- FRD-022 — MCP server surface: R5c/R6 require the released/committed bundle to represent the current server surface, remain deterministic, and pass plugin:check, MCPB parity, and smoke expectations. This plan refreshes the artifact only; it does not change the surface.

## Steps

1. Create the recorded MCP-043 branch/worktree from origin/main and take the ticket through MCP.
2. Run npm run plugin:build using the canonical standalone build/copy path.
3. Confirm the only tracked source diff is plugins/kanmer/mcp/kanmer-mcp.cjs; compare fresh and committed SHA-256 bytes and run git diff --check.
4. Run npm run plugin:check and npm run mcpb:check; retain exact exits/output.
5. Run the relevant MCP smoke/protocol, MCP-server typecheck/build, and scripts rails; preserve any unrelated or environment-only failure without weakening assertions.
6. Commit the artifact-only change, write the post-implementation report, push, open a PR, record traceability, and move MCP-043 to Review for independent review.

## Verification

The report will identify the merge-base under test, artifact SHA-256 values, exact diff scope, parity checks, MCP smoke/protocol counts, MCP-server typecheck/build, scripts rail, and git diff --check exit codes. Proof is intentionally deferred to kanmer-verify after merge.

## Risks / open questions

- A linked-worktree dependency resolution or missing MCPB tool may make a rail environment-only; retain the exact failure and rerun only with a documented, non-source setup correction.
- A diff outside the committed artifact means the scope is not bounded; stop and investigate rather than committing it.
