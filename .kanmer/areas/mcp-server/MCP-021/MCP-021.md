_Rescoped 2026-08-21: Cloudflare Tunnel-only release boundary._

## What

Define the provider-neutral tunnel adapter contract and implement cloudflared as the first adapter for one operator-provisioned, locally managed named Cloudflare Tunnel.

## Why

The remote HTTP host is provider-neutral, but the first shipped tunnel has one tightly bounded mode: one exact public HTTPS hostname maps to one bearer-authenticated loopback `/mcp` origin. OpenAI Secure MCP Tunnel remains an independent OpenAI-managed stdio path documented by [[DOC-010]], not an adapter or dependency of this ticket.

## Approach

- Expose a small adapter interface consumed by the Cloudflare GUI lifecycle ([[GUI-095]]) and connector doctor ([[MCP-027]]).
- Validate a single named-tunnel credential-file mode, generate one exact hostname-to-loopback ingress rule plus terminal `http_status:404`, and verify it with cloudflared's ingress validation/rule commands.
- Do not implement application auth ([[MCP-026]]), transport ([[MCP-025]]), Cloudflare Access, Quick Tunnels, remote-managed tunnel tokens, Cloudflare account/DNS automation, or a Worker-hosted MCP service.

## Verification

- [ ] The adapter exposes the authenticated local HTTP endpoint through the named-tunnel contract without receiving the bearer token.
- [ ] Generated ingress accepts only the configured hostname, maps it to the exact loopback origin, and terminates unmatched traffic with 404.
- [ ] The doctor and fake-provider tests distinguish provider/config failure from bearer, host, and board failure.
