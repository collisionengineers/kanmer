## What

An agent should be able to work the board with the desktop app **closed**, and
Kanmer should ship a `.mcpb` bundle installable directly into Claude Desktop.

## Why

Nothing plans this today. FRD-010 uses the word *headless* for **dispatch** —
spawning provider CLIs — not for board access, and no FRD covers running without
the GUI. The MCP server is registered as `command = <Kanmer.exe>` with
`ELECTRON_RUN_AS_NODE=1` (`connect.ts`), so it already runs without a window,
but nothing states that as a supported mode or defines its edges.

`.mcpb` is separate and simpler: a bundle format for installing an MCP server
into Claude Desktop without a CLI. Kanmer has no such artefact.

## What is *not* a blocker

**Git auto-sync.** The board worktree's periodic commit is a **convenience**, not
a correctness requirement: once `.worktrees/kanmer` exists, the board is plain
files on disk that the server reads and writes directly, and the user can commit
by hand whenever they like. So headless does not need a new committer, and this
ticket should not grow one. The precondition is that the **worktree already
exists** — which the app sets up — so the honest scope is "works once set up",
not "sets itself up".

## Approach

- Establish what already works with the app closed, by testing rather than
  reasoning: reads, writes, gate evaluation, and that the board is still
  consistent afterwards.
- Define the supported mode in FRD-022 so it stops being accidental: what an
  agent may rely on with no GUI running, and what it may not (an unsynced board
  branch being the obvious one).
- Sequence against [[MCP-005]]: shipping the server outside `$INSTDIR` is close
  to a precondition for a standalone story, and the two should not fight.
- Add a `.mcpb` build target with the `--root` argument surfaced, since a desktop
  install has no project context to infer from.

## Verification

- [ ] With the app never launched, an agent can list, create, move and gate-check
      tickets against an existing board worktree, and the board is consistent
      afterwards.
- [ ] The unsynced-board case behaves sanely and is documented, rather than
      being silently repaired by a new background process.
- [ ] A `.mcpb` installs into Claude Desktop and connects to a chosen project
      root.
- [ ] FRD-022 describes headless as a supported mode with stated limits.
