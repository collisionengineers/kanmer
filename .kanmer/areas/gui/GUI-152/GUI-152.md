## Problem

The board renders every ticket in every one of the six columns with no bound, no scope and no navigation rail; on a 384-ticket board the default view is one unbounded scroll and the Done column dominates. Alex selected the **Focus Board** design (`Kanmer_Upgrade_Pack_2026-09-05/approved-ui/01-focus-board.html`, the unchanged reference) as the product direction. [[GUI-151]] delivered the accepted current-UI mockup; this ticket implements the approved design against real data.

## Outcome

A left rail with named scopes (Active work = Preparing→Verifying, All tickets, Backlog, Completed, Archived) and areas, each with live counts; columns limited to the scope's stages; four visible cards per column with a per-column pager and "start–end of total"; compact cards showing the most relevant group plus a "+N" indicator; counts that distinguish total, filtered and shown; view preferences remembered per logical project. Existing operations (detail editor, filters, search, command palette, context menu, standup, activity, settings, archived restore/delete, drag/drop and Ctrl+Arrow moves) remain reachable and unchanged in semantics.

## Acceptance

- Data pipeline is project → scope → filters/search → deterministic sort → page; filtering after slicing is impossible by construction; a page is clamped/reset when the filtered set changes; a column with matches outside the old page never shows a false empty state (unit tests on a synthetic 2,000-ticket board).
- Four cards per column is a display bound only; every ticket stays reachable via paging, search and scopes; search reaches all scopes and opens the item even when outside the visible page.
- Manual reorder uses the full column order, not the visible page; cross-page drop is refused or routed to the menu move.
- Keyboard: rail and pager operable without a pointer, visible focus, `aria-current` on the active scope; reduced motion respected; narrow window collapses the rail.
- Preferences (`scope`, rail collapsed, column pages) stored in `settings.json` keyed by `project_id`, never written to tickets.
- `Board.test.tsx` extended; new `Sidebar.test.tsx`, `scopes.test.ts`, `paging.test.ts`; `npm run test -w @kanmer/gui`, `npm run typecheck`, `npm run build -w @kanmer/gui` green; manual pass on a small board, the live board, an empty filtered scope and retired non-PASS records.
- Governing doc: new `docs/functional/frd/FRD-036-focus-board.md` written via `kanmer-docs` (this ticket carries `docs_todo`).
