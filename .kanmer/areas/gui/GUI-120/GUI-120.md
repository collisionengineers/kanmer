Independent review finding from GUI-118 PR #219 at head e09009b2.

connectProject() correctly updates every open context after a user-scoped native Connect, but its broadcast loop iterates [id, project] and emits { projectId, ... } using the initiating projectId instead of id. With two open projects, status payloads for the other projects are mislabeled; App.tsx filters status events by its project root, so those contexts do not receive their updated nativeReconnectRequired state. Add a multi-project production-caller regression and emit the loop id. This blocks GUI-118 review/merge.
