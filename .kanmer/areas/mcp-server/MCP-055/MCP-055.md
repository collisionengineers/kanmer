## What
Since FRD-029 landed ([[CORE-114]]), `ok()` in `packages/mcp-server/src/index.ts` attaches `structuredContent: { project }` to **every** successful tool result while the real payload stays only in the `content[0].text` block. MCP clients that prefer `structuredContent` when it is present — Claude Code is one — therefore display **only** the three-field project stamp and drop the payload. Observed 2026-09-02 on the installed v0.4.0 server (`efe89029`) from Claude Code: `get_status`, `migrate_board`, `list_groups` and every other call returned just `{"project":{"project_id":…,"board_id":…,"fingerprint":…}}`. The same requests over raw JSON-RPC return a full 3.5 KB text block, so the server is correct and the loss is entirely in what the client chooses to render. v0.3.12 did not set `structuredContent`, so this is a **0.4.0 regression** that makes the promoted control plane unusable from Claude Code without a side-channel shim.

The MCP specification says structured results SHOULD be mirrored in a text block for backwards compatibility — i.e. `structuredContent` is meant to be the *whole* result, not a decoration. Error results (`errors.ts` `failCoded`) already put the error object in `structuredContent`, which is why errors still display fully.

## Why it is a horizon member
FRD-029 acceptance ("every response identifies the logical project") was implemented in a way that breaks the primary agent host. "Stable controls candidate" (FRD-035/ADR-0021) is meaningless if the stable server cannot be driven from the controller. Blocker class for 0.4.1.

## Approach (for the planner)
- Make `structuredContent` the complete result: `{ ...payload, project }` when the payload is a plain object, or `{ result: payload, project }` when it is an array/scalar, so text and structured views agree. Keep `structuredContent.project` (smokes assert it: `smoke.mjs` ~483, `smoke-protocol.mjs`).
- Consider declaring `outputSchema` only if the SDK requires it for structuredContent; otherwise leave undeclared.
- Add one regression test: for a representative read (`get_status`) and a representative write, `JSON.parse(content[0].text)` deep-equals `structuredContent` minus `project`.
- Verify from a real Claude Code session against the packaged bundle before Done (promotion acceptance shape from [[CORE-136]]).

## Verification
`npm run verify` green; both smokes green; a Claude Code session on the built bundle shows the full `get_status` payload. Proof cites the exact merged SHA and the Claude Code observation.
