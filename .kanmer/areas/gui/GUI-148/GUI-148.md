## Why

Raised as finding F-001 of the GUI-147 review (PR #311, head `ff6a87c8`), dispositioned `deferred-to-ticket` because the fix is a renderer behaviour change that GUI-147's plan explicitly forbade ("Settings.tsx — scope-aware tooltip wording only"; "Forbidden: adding a new renderer feature surface").

GUI-147 correctly gave Claude's disconnect the host state to reverse that FRD-012 R4 always implied: `disconnectAgent("claude", …)` now runs

```
claude plugin uninstall kanmer@kanmer -s user -y
claude plugin marketplace remove kanmer
```

Both are **user-scoped**. The Disconnect button, however, sits in a per-project Settings panel, and `ConnectSection.run()` in `apps/gui/src/renderer/src/components/Settings.tsx` (~L492) shows its user-scope confirmation for `grok` and `antigravity` only:

```ts
if (target === "grok" || target === "antigravity") {
  const approved = window.confirm(
    `${host}'s Kanmer plugin is user-scoped. …affects every ${host} workspace for this user. Continue?`,
  );
  if (!approved) return;
}
```

So a user with Kanmer connected in projects A and B who presses Disconnect in project A silently removes the plugin — skills and the `plugin:kanmer:kanmer` MCP server — from project B's Claude sessions too. That is exactly the silent-control-plane-breakage class HZN-008 exists to prevent, and the repository already decided this class warrants a confirmation.

Connect has the same asymmetry (Claude's install is user-scoped and always was), but disconnect is the newly destructive half.

## Outcome

- A per-project Connect/Disconnect that mutates user-scoped host state asks for confirmation naming the scope, for **every** such host — Claude included — rather than by an enumerated provider list that must be remembered when a new host gains user-scoped state.
- Prefer deriving the condition from the provider spec (e.g. `install.kind === "plugin"` or a marketplace spec that declares `hostRemoveCommands`) so the next host is covered by construction.
- Wording matches the existing Grok/Antigravity copy.

## Verification

- A renderer test (or the existing Settings test surface) proves the confirmation is offered for Claude disconnect and that declining it makes no IPC call.
- Grok/Antigravity wording and behaviour are unchanged.
- Manual: Kanmer connected in two projects; declining the Claude confirmation in project A leaves `claude plugin list` reporting `kanmer@kanmer` at user scope.
