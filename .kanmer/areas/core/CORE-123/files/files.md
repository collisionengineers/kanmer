## Ripple effects

- Callers of `evaluateMergeGate` with phase-2 evidence: only `check-pr.mjs`. Legacy (no-phase-2) path unchanged.
- `parseReviewAttestation` is used by `packages/core/src/store.ts` for the Review→Implementing backward move (CORE-121); extra optional fields must not change its `valid` decision for existing files.
- `KanmerGitStatus` is serialised over IPC to the renderer; new optional field is additive.
- `smoke.mjs` and `smoke-headless.mjs` read `get_status`; additive key only.
- `plugins/kanmer/mcp/kanmer-mcp.cjs` must be regenerated in the same commit.
- Existing board attestations (`scratch/review.md` on many Done tickets) lack `board_sha` — the gate must treat that as "unrecorded", not stale.

## Deliberately out of scope

- Making the MCP server push the board (no git in core/MCP writes; GUI remains the sync owner).
- Turning strict on by default or removing the compatibility warnings (one-release flag per ticket).
- Lease/revision contracts (CORE-114/115), reviewer-settlement semantics of `expected_reviewers` (SKILL-037) — this ticket only parses and carries those fields.
- A GitHub App or merge queue (ADR-0016 non-goals).
