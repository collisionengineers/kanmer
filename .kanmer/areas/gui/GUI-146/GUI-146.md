## Symptom

`npm run release -- 0.4.0 --ticket CORE-136` (fresh clone of `main` at a744fd76) passed the whole verify rail, the version bump, the bundle rebuild and `plugin:check`, then failed at step 6 `npm run build -w @kanmer/gui`:

```
error during build:
../../packages/core/dist/index.js (675:9): "createHash" is not exported by "__vite-browser-external", imported by "../../packages/core/dist/index.js".
```

Log: `C:\Users\Alex\Documents\KanmerBackups\release-prepare-0.4.0.log`. The release clone was reset to `main`; no branch, tag or PR was created.

## Cause

`apps/gui/src/renderer/src/lib/standup.ts:2` — `import { isCaptureItem } from "@kanmer/core";` — added by [[CORE-117]] (PR #298). It is the only runtime (non-`type`) import of the Node entry anywhere under `apps/gui/src/renderer`. Every other renderer import is `import type`, and the two existing runtime helpers (`UI_STAGES`, `uiStageName`) go through `apps/gui/src/shared/stages.js`. Vite bundles the whole single-file `packages/core/dist/index.js` into the renderer, and its `import { createHash } from "node:crypto"` cannot resolve in a browser context. `packages/core/src/browser.ts` is the browser-safe entry (`@kanmer/core/browser`, exported in `packages/core/package.json`), and it already re-exports `profiles.js`, where `isCaptureItem` lives.

`npm run verify` (`scripts/verify.mjs` `VERIFY_STEPS`) never runs `npm run build -w @kanmer/gui`, so PR #298 and every later PR passed CI with a GUI that no longer bundles. AGENTS.md §10 item 4 lists the GUI build as a required check; the rail does not enforce it.

## Fix

1. `apps/gui/src/renderer/src/lib/standup.ts`: import `isCaptureItem` from `@kanmer/core/browser`.
2. `scripts/verify.mjs`: add `npm run build -w @kanmer/gui` to `VERIFY_STEPS` after the core/server build so the PR rail and the release rail both prove the renderer bundles. Update the `npm run verify` row in AGENTS.md §6 in the same PR.
3. A guard that fails fast on the next regression: a test under `apps/gui` (or `scripts/*.test.mjs`) that scans `apps/gui/src/renderer/**/*.{ts,tsx}` (non-test files) and fails on any non-`type` import from `@kanmer/core` (the Node entry), allowing `@kanmer/core/browser`.

## Not in scope

No change to what `browser.ts` exports beyond what the renderer needs today; no vite aliasing or polyfill of Node builtins; no other renderer refactor.
