## What

`apps/gui/src/main/kanmerGit.test.ts` intermittently fails on Windows. Two
symptoms, usually together, on the same case:

```
FAIL src/main/kanmerGit.test.ts > ensureBoardWorktree reconciliation
     > moves a worktree left on the old branch onto the configured one
Error: Test timed out in 5000ms.
Error: EPERM, Permission denied: \\?\C:\Users\PC\AppData\Local\Temp\kanmer-git-sBusm2
 ❯ src/main/kanmerGit.test.ts:49:3
    48| afterEach(() => {
    49|   rmSync(dir, { recursive: true, force: true, maxRetries: 3 });
```

## Why it matters

It makes `npm test` non-deterministic, which is the rail every ticket closes
against. During [[MCP-011]] it failed twice and passed three times in one
sitting, costing several minutes each time to establish it was not a regression.
A rail that fails at random trains people to re-run instead of read.

## Established as pre-existing, not caused by any one change

Measured during [[MCP-011]]'s verification, same machine, same session:

```
merged main 29bee81   run 1,2,3: EXIT=0  7 passed
parent      6c3ae77   run 1:     EXIT=1  1 failed, 6 passed
                      run 2:     EXIT=0  7 passed
```

It fails on a commit that predates MCP-011 entirely. Load-sensitive: it showed up
while other agents were doing git work in the shared checkout.

## Likely causes, both plausible and not exclusive

1. **The 5s default vitest timeout is too tight for real `git worktree`
   operations on Windows.** Sibling cases in the same file already take
   2.5-4.1 seconds when the machine is idle, so the margin is thin. A per-file
   `testTimeout` would remove the first symptom.
2. **`rmSync` races Windows file locks.** `maxRetries: 3` is already there but
   has no `retryDelay`, and git can still hold handles into the worktree
   directory as the process winds down. `retryDelay` plus tolerating `EPERM` in
   teardown (a leaked temp dir is not a test failure) would remove the second.

Fixing (2) alone would turn some failures into passes while leaving the timeout;
worth doing both.

## Verification

- [ ] The named case run 20x in a row with the machine under concurrent git load,
      zero failures — a flake is only fixed when it is *shown* not to recur, and
      a single green run proves nothing here
- [ ] Teardown failure cannot fail a test that otherwise passed
- [ ] No blanket global timeout raise that would mask a genuine hang elsewhere
