## Why
Several on-device MCP clients import servers from a pasted JSON configuration and accept only a literal `npx` or `uvx` stdio command. Kanmer's shipped native plugin descriptor uses `${KANMER_NODE:-node}` plus a bundle path, so those importers reject it outright. The defect was first observed with **Qwen Desktop** and later reproduced with the Grok JSON Configuration importer; it is a client-class limitation, not a Grok-specific one, and will apply to any client with the same importer rule. (Retitled 2026-09-02 from "Support Grok npx-only MCP JSON importer" for that reason; nothing else about the record changed.)

The repository currently claims compatibility for these hosts through their CLI/plugin surfaces (FRD-012), not through this importer path.

## Outcome
Establish one supported invocation that such importers accept — for example a published `npx`-runnable launcher package or an equivalent documented shim — without exposing secrets or machine-specific paths. Update the provider contract (FRD-012 registration matrix) and the user guidance so the pasteable JSON is generated by Connect rather than hand-written. The solution must be client-agnostic: the same JSON must work for Qwen Desktop, Grok and any other npx/uvx-only importer.

## Verification
Prove an actual tool call (`get_status` against a real board) through at least two npx/uvx-only clients using the generated JSON, not merely that the server appears in a listing. Existing Connect tests and the plugin-bundle tests stay green.

## Approach decision 2026-09-02

The operator chose a **Connect-generated local `npx` shim**: Connect writes a small local package (or points `npx` at the installed runtime generation under `%LOCALAPPDATA%\Kanmer\mcp\current`) so the pasteable JSON is a literal `npx <local-path-or-package>` invocation that npx/uvx-only importers accept. No registry publish and no npm token; `@kanmer/mcp-server` stays private. Depends on [[GUI-147]] (shared `connect.ts`/`providers.ts` surface). Scheduled for 0.4.2.
