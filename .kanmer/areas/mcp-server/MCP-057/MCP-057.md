## Problem

`kanmer-verify` creates a disposable detached worktree at the merge SHA immediately after confirming the merge, then runs the packet's checks there. It never looks at the `verify` job that `pr.yml` already ran on the push to `main` for that exact SHA — the run the workflow comment itself calls "the bound post-merge receipt kanmer-verify consumes". Every verified ticket therefore re-runs the whole Windows rail locally, which is the single largest source of repeated execution and host contention.

## Outcome

Verification resolves the ticket's obligations, obtains the exact PR merge SHA, looks up the push-to-`main` `verify` run for that SHA, classifies each obligation as satisfied / missing / rejected, creates a worktree only for missing obligations, and writes one truthful proof that cites the receipt. A PR-head run, a cancelled or skipped job, or a run on another SHA never counts. The parts that are validated by code and the parts that remain human judgement are labelled as such.

## Acceptance

- Exact matching evidence (push event, `verify` job, `success`, `headSha` equal to the full merge SHA) causes no new full run and no verification worktree.
- Wrong SHA, `pull_request` event, cancelled / skipped / timed-out run, missing `verify` job or unknown receipt kind is rejected by `assessReceipt` with a reason; table-driven tests cover each.
- An in-progress run is waited on once (`gh run watch`) rather than duplicated locally.
- Proof frontmatter gains an optional `receipts[]` list beside `attempts[]`; existing proofs without it are unaffected and unknown fields are preserved; `proofEvidence()` surfaces receipts and rejects one whose `head_sha` disagrees with the PR merge SHA.
- Uncovered obligations (manual GUI, installed-host, Windows-lock, provider checks) remain missing and are run in the worktree as today.
- The skill and the proof say explicitly that provider provenance and the "packet ⊆ npm run verify" coverage judgement are human-reviewed in this release.

## Out of scope

A receipt store, reuse-key digests, ancestry-based reuse, a provenance-verifying host adapter, a new MCP tool, arbitrary shell execution. Typed `attempts[]` validation is [[CORE-129]].

## Technical seam

`plugins/kanmer/skills/kanmer-verify/SKILL.md` workflow steps 3–5 reordered. New pure `packages/core/src/proof-receipts.ts` (`parseProofReceipts`, `assessReceipt`) beside `review-attestation.ts`, not exported from `browser.ts`. `packages/mcp-server/src/reconciliation.ts` `proofEvidence()` decodes `receipts[]`; the merge-SHA comparison introduced by CORE-133 extends to receipts. Tests: `packages/core/src/proof-receipts.test.ts`, `packages/mcp-server/src/reconciliation.test.mjs`.
