## Problem

On merged main after MCP-029, `npm run plugin:check` fails even though the source and committed plugin bundle are functionally equivalent. A fresh standalone build resolves `js-yaml` at `node_modules/js-yaml`, while the committed bundle was generated with it nested under `gray-matter/node_modules/js-yaml`. The resulting byte difference is limited to generated module-path comments, but the checker intentionally compares bundle bytes and therefore reports a failure.

## Evidence

- `npm run build`, core tests, MCP smoke, and protocol smoke passed on merged main.
- `npm run plugin:check` failed: “Committed plugin bundle differs from a fresh build — run npm run plugin:build.”
- A no-index diff shows 60 changed lines, all generated `js-yaml` module-path comment/function-label paths; no runtime implementation difference was observed.
- MCP-029's PR worktree passed its bundle comparison, so the outcome depends on dependency hoisting/layout rather than the ticket source.

## Desired outcome

A clean main checkout with the lockfile-resolved dependencies can build and pass `npm run plugin:check` reproducibly. Preserve the check’s ability to detect real source/bundle drift; do not paper over a mismatch by weakening it blindly.

## Verification

- Reproduce with alternate valid dependency layouts or a controlled fixture.
- `npm run plugin:build` followed by `npm run plugin:check` passes from main.
- The committed bundle is deterministic across the supported install layout(s), or the check compares a deliberately canonical output that remains sensitive to real drift.
