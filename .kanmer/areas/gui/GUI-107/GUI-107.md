## What

Expose the inline `requires` editor when a user selects the `custom` profile in TicketCreate and Editor, matching the documented profile-picker behavior.

## Why

The historical GUI-008 record claims this behavior, but current TicketCreate/Editor flows expose profile selection without an editor for custom requirements. GUI-007 owns the Settings profile editor; this ticket restores the ticket-form behavior without duplicating core validation.

## Verification

Create/edit a ticket with profile `custom`, set a boundary requirement, save and reload, and prove the same map reaches the MCP/core model and gates. Unknown boundaries/types must be rejected using the existing renderer validation pattern.

## Non-goals

Do not change core profile vocabulary, gate semantics, or unrelated Settings profile work.


## Outcome

PR #151 (https://github.com/collisionengineers/kanmer/pull/151) merged as 241ff13e048e4535a69d7375b9f734d9a4606cf8. The custom requirements editor shipped in TicketCreate and Editor with deterministic test/build/typecheck verification. No follow-up ticket or deployment was created; manual Electron visual evidence remains explicitly parked as unavailable.
