## What

Kanmer's Claude plugin install command **fails outright**, and the failure is
swallowed. Split out of [[MCP-009]], which measured it against the real CLI.

Three linked defects:

1. `pluginRoot()` returns `plugins/kanmer`, but the marketplace manifest lives at
   the **repo root** (`.claude-plugin/marketplace.json`). So:
   `claude plugin marketplace add …\plugins\kanmer` →
   `✘ Marketplace file not found at …\plugins\kanmer\.claude-plugin\marketplace.json`,
   exit 1. Pointed at the repo root instead it succeeds, and
   `claude plugin install kanmer@kanmer` then reports `✔`.
2. `connect.ts:152` swallows that non-zero exit into "plugin cmd skipped", so the
   user is never told.
3. `apps/gui/electron-builder.yml` ships only `plugins/kanmer` — **neither**
   marketplace JSON. The packaged app therefore has no local marketplace source
   at all, despite a comment claiming one. The v2 plan explicitly required both,
   so this is a regression against a written decision, not an oversight.

Two further disagreements found in the same audit, in scope here because they are
the same class:

- **Two marketplace names.** `.claude-plugin/marketplace.json` says `kanmer`;
  `.agents/plugins/marketplace.json` says `kanmer-plugins`. Both confirmed live.
- **Two bundled MCP paths** with different variables: `./mcp/claude.mcp.json`
  uses `${CLAUDE_PLUGIN_ROOT}`, `./.mcp.json` uses `${PLUGIN_ROOT}`. Whether
  `${PLUGIN_ROOT}` expands at all per host is unverified — check it, do not assume.

## Why

This is the blocker under "the plugin isn't helping as much as I hoped". The
marketplace path has never worked from the packaged app, and nothing said so
because the error was caught and relabelled.

Note the swallowing is the more important half. A command that fails loudly gets
fixed in a day; a command that reports "skipped" survives a release cycle.

## Approach

- Point the marketplace command at the directory that actually holds the
  manifest, verified by running it — not by reading paths.
- Stop swallowing a non-zero exit from an install command. Surface it.
- Ship the marketplace JSON(s) in the packaged app, or state with evidence why a
  packaged app cannot use a local marketplace and remove the claim instead.
- Reconcile the two marketplace names and the two `${…}_ROOT` variables, or
  document why both must exist.
- Follow [[MCP-009]]'s method: every capability claim carries the command and its
  output, and a probe needs a positive control.

Related but separately owned: [[MCP-011]] fixes the manifests' frozen `0.1.0`
version (which also freezes codex's cache path at
`…\kanmer-plugins\kanmer\0.1.0`).

## Verification

- [ ] `claude plugin marketplace add` + `claude plugin install kanmer@kanmer`
      succeed from a clean profile, with the commands and output recorded.
- [ ] The same works from the **packaged** app, not only the repo checkout.
- [ ] A failing install command produces a visible error, asserted by a test with
      a deliberately broken path.
- [ ] Marketplace names and plugin-root variables agree across every manifest and
      `providers.ts`, or the disagreement is documented with its reason.
