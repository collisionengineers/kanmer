## What
Ensure `KanmerHttpHost.start()` rolls back constructor resources when pre-bind project/fingerprint resolution rejects, including the unref'd sweep timer, and remains safely closeable/idempotent after failure.

## Why
MCP-036 moves `projectFingerprint()` before the listener `try/catch`, so a no-board/fingerprint failure now occurs before binding but bypasses `rollbackStart()`. A runtime probe on PR #108 reports `httpServer.listening === false` while `host.sweepTimer._destroyed === false`; the failed host retains its interval until process teardown. This violates MCP-036's acceptance that failed startup leaves no resource and FRD-025/ADR-0017 bounded lifecycle expectations.

## Verification
- Add a regression that injects/fakes project-resolution failure and proves the timer is destroyed, no listener exists, and repeated close does not throw.
- Re-run HTTP tests, build, smokes, typecheck, and diff checks.

This review follow-up blocks [[MCP-036]] until fixed and independently reviewed.
