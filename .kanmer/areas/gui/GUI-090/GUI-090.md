## What

Give the GUI the itemised staleness report [[CORE-023]] shipped for agents.
`get_status.repo` — `{ upToDate, stale: [{ artefact, state, detail, fix }] }` —
reaches every agent through the MCP orientation call. **The GUI cannot see it at
all.**

Split out of CORE-023 by an explicit operator decision: the GUI surface roughly
doubled that ticket, and MCP-only was the scope chosen. The detection is done
and shipped; this is only the second surface for it.

## Why

The GUI has **no MCP client** — it calls `@kanmer/core` directly (`snapshotOf`,
`apps/gui/src/main/index.ts`) — so a `get_status` field does not reach it by any
route. Its entire staleness UI today is:

- the format banner (`App.tsx`, around the migration prompt), which covers row 1
  of ADR-0015's table and nothing else; and
- the **"Update skills" button**, which compares `plugins/kanmer/.claude-plugin/plugin.json`
  against the installed stamp. CORE-023's research found that manifest frozen at
  `0.1.0` while the product was `0.3.2`, so the button has **never lit up for any
  release ever shipped**. (MCP-011, #52, has since fixed the manifests — worth
  re-measuring whether it can now fire, and whether this ticket should replace it
  outright rather than sit beside it.)

So a human looking at the Kanmer app is blind to everything except board format,
while an agent in the same repo is told `.claude/skills` is three files behind.

## Approach

`detectStaleness()` already lives in `@kanmer/core` precisely so both surfaces
share one implementation — no detection logic belongs in this ticket.

- **IPC**: a new handler in `apps/gui/src/main/index.ts` + channel and result
  type in `apps/gui/src/shared/ipc.ts`. A **separate handler**, not a widening
  of `snapshotOf` — that is on the hot refresh path and this reads ~35 files per
  skills destination.
- The GUI must supply the two arguments the MCP server supplies: `repoRoot`
  (the source checkout, not the board worktree) and `bundledSkillsDir`. The
  server resolves the latter from its own path (`packages/mcp-server/src/bundled.ts`);
  the GUI knows its own layout instead — `connect.ts:36-70` already resolves the
  three bundle shapes for `installSkills`, so reuse that rather than inventing a
  fourth answer.
- **Renderer**: surface near the existing format banner. **A `compensated` row
  must never become a permanent nag** — every board in existence has one
  (`board.yml` omitting `questions-resolved`), so the banner must key off
  `upToDate` (i.e. `behind` rows only) and put the rest behind a disclosure.
  Getting this wrong makes the app show a warning to every user forever, which
  is the exact failure ADR-0015's four-state vocabulary exists to prevent.
- Each `fix` string is already written for a human; render it, don't rewrite it.
- Consider wiring the banner's action to the existing reconnect/`kanmer-setup`
  path (FRD-013), since the detector deliberately never repairs anything.

## Also in scope — the small inversion CORE-023 deferred

`packages/core/src/staleness.ts` currently **mirrors two lists** from
`apps/gui/src/main/providers.ts`, with comments saying so at both definitions:

- `SKILL_DESTINATIONS` (`.claude/skills`, `.agents/skills`, `.grok/skills`) vs
  the `copySkills` `skillsDir` values, and
- the registration file paths (`.mcp.json`, `.codex/config.toml`,
  `.grok/config.toml`, `opencode.json`, `.agents/mcp_config.json`) vs each
  provider's `configPath`.

Core cannot import the Electron main process, so one side has to hold the copy.
Once the GUI depends on the detector anyway, invert it: **`providers.ts` reads
these from core**, and the duplication goes away. ADR-0015's Consequences
section records this as the intended resolution.

- [ ] A repo whose only finding is `compensated` shows **no** banner.
