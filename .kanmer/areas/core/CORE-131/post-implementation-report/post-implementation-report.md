## Mapping to the governing docs

`refs`: `docs/functional/frd/FRD-028-rescue-and-reconciliation.md`.

- **AC2 — apply only a still-current action, audit it, structured conflict
  otherwise.** The boundary re-collects through the *same* `reconcileTicket` the
  dry run used, then refuses in order: `RECONCILIATION_INCONCLUSIVE` (no
  recommendation, or a legacy-layout ticket with no revision),
  `REVISION_CONFLICT` (the freshly collected revision is not the one being
  applied), `RECONCILIATION_DRIFT` (the recorded revision or stage moved *during*
  collection). Only then does it delegate, and `expectedRevision` goes into the
  verb's own locked CAS. The audit is one `## Transitions` line per applied
  action.
- **AC3 — typed routing.** `implementation` → Implementing, `plan` → Preparing,
  `transient`/`inconclusive`/absent/unrecognised → no recommendation, ticket
  stays in Verifying. Merged Review → Verifying and PASS Verifying → Done were
  already classified and now apply. Abandoned claims recover via
  `transferTicket`.
- **AC4 — dirty preserved, cleanup only for terminal+clean+authorised.** The
  expired-claim route sits deliberately *before* the dirty/missing stop, so a
  dirty workspace is still recoverable; recovery is a transfer, which deletes and
  cleans nothing. The only release is `RELEASE_CLEAN_TERMINAL_CLAIM`, gated on
  `done` + `clean` + `matches-claim`, and it releases the **claim**, not the
  worktree.
- **AC1 not regressed.** `reconcile_ticket` keeps `readOnlyHint: true` and smoke
  still proves the dry run leaves the ticket byte-identical.
- **AC5 not regressed.** `release.state` stays hard-coded `not-applicable`; the
  `RELEASE_EVIDENCE_PRESERVED` and `BOARD_WORKTREE_PROTECTED` refusals still
  return before any recommendation; no path force-pushes or bypasses a check.

CORE-121's backward-move contract is **not** widened: no `reconcile:` prefix, no
third authority. A test walks the whole ladder — no reason →
`BACKWARD_MOVE_NEEDS_REASON`; a non-operator reason →
`REVIEW_RETURN_NEEDS_ATTESTATION`; an `operator:` reason → the move, with
`review_round` incremented. PR #286 passed **no reason at all**, so its path is
dead against current `main`; nothing was cherry-picked from
`core-113-rescue-reconciliation`, and that branch was not touched.

## Deviations

1. **`packages/mcp-server/src/errors.ts` is modified but is not in the plan's
   Expected-files table** (it is listed as a context file). Two members were
   added to `KanmerErrorCode`. The plan requires the boundary's refusals to be
   "`KanmerError`/`failCoded` structured codes", which is not expressible without
   them. Nothing else in the file changed and it is not on the `## Do not modify`
   list.
2. **`npm run verify` was run from `.worktrees/core-131`, not the main
   checkout.** The plan's rule exists because `plugin:check` refuses in a linked
   worktree, but `scripts/check-plugin-sync.mjs:50-66` actually refuses on
   whether the checkout **owns its `@kanmer/core` resolution** — its own comment
   says *"Asking git whether this is a linked worktree was only a proxy for this
   property."* `npm ci` gave this worktree that property and `plugin:check`
   passed here (bundle bytes match, isolated handshake lists 40 tools). Switching
   the shared main checkout onto this branch would disturb a resource other lanes
   are actively using, for no verification gain.
3. **The fresh worktree had no `node_modules`,** so `@kanmer/core` resolved up to
   the *main* checkout's stale `packages/core` and `npm run typecheck` exited 2
   on CORE-116 exports that do exist on this base. Fixed with `npm ci` in the
   worktree. Not a code defect, but it decided (2) and is recorded so the next
   worker does not re-diagnose it.
4. **`RECONCILIATION_DRIFT` is implemented as a revision-and-stage recheck
   against the store immediately before delegating**, rather than as a second
   comparison of the freshly-classified action against itself. The tool
   deliberately takes no caller-supplied action, so there is nothing else to
   compare it to; re-reading `getRevision` and the item catches the real window
   — collection spawns git/gh and takes seconds, during which another controller
   can move the ticket. The plan's own words ("belt and braces; a revision match
   should already make this unreachable") are satisfied, and the verb's CAS would
   refuse it regardless.

## Risks and residual

- **The expired-claim route pre-empts the Verifying/Done routes** for a
  non-terminal, non-Review stage. This is the plan's specified ordering and is
  the safe direction: an abandoned lease is reclaimed first, and the new
  controller's next `reconcile_ticket` sees `MOVE_TO_DONE`. It costs one extra
  round trip in that corner. A test pins that a merged Review still advances
  rather than being reduced to a transfer.
- **F-016** (`GH-3867261023`): failing or pending required checks pre-empt the
  closed-unmerged Review rollback in the classifier. Inherited from CORE-122,
  dispositioned minor there, explicitly out of scope here per HZN-008's scope
  discipline. Recorded as residual risk; no follow-up ticket filed.
- `reconcile_ticket`'s JSON result changed shape **additively** (`ticketId`,
  `revision` on the recommendation; `failureClass` on a FAIL proof). No consumer
  reads it besides the tests and smoke updated here; the GUI does not call it.
- `scratch/execution.md` gains `reconcile <ACTION> …` transition lines. The
  existing `<verb> <from> → <to> …` grammar is unchanged, so `## Transitions`
  parsers see a new line shape but not a new format.
