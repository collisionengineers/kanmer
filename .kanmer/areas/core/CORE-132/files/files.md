## Ripple effects

- **`plugin:check` compares bundle bytes** — any `packages/**` change needs
  `npm run build && npm run plugin:build` before commit, or the rail fails.
- **The tool roster is asserted in two smoke files and pinned in prose in four
  more.** Missing one is a red rail, not a silent drift.
- **`get_status` is read by `kanmer-setup`, the GUI and every skill's
  orientation step** — a new key is additive but appears in many transcripts.
- **`reconcile_ticket`'s evidence shape is asserted** in
  `packages/core/src/reconciliation.test.ts` and `smoke.mjs:3048`. The shape does
  not change; only the producer does. Existing `not-applicable` assertions must
  keep passing on a board with no release records — that is the regression that
  proves the collector is neutral by default.
- **`.kanmer/releases/` is committed on the board branch**; the lock beside it is
  already covered by the board's `.gitignore` (`.kanmer/**/*.lock`).
- **Board format is unchanged** (still 3): additive sidecar, defaults resolved at
  read (`migrate.ts:498-500` doctrine).
- `docs/contributing/doc-structure.md` mirror / `npm run verify:docs` — the
  glossary edit touches `/docs/`.

## Out of scope (deliberately)

- **CORE-116's half of FRD-031** — AC1, AC5, the rest of AC2 and the
  unmerged-branch edge case. Shipped, reviewed criterion by criterion; not
  re-implemented and not "improved".
- **`gates.ts` / `profiles.ts`** — nothing there may read a release record, or
  recording a release becomes a way to skip proof (ADR-0005; CORE-116's
  "delivery state is not a gate" regression must keep passing).
- **`board.yml`** — the release lease is deliberately not board config; it must
  stay invisible to v0.3.12.
- **`.github/workflows/*.yml`, `scripts/release*.mjs`** — Kanmer's own repository
  and artifact-publishing policy. FRD-031 forbids changing it to demonstrate
  another policy; `release-flow.mjs` is not board delivery state.
- **GUI surfaces for the release channel** — after this lands; `get_status.release`
  is the read the GUI would consume.
- **A second definition of "hotfix"** — `deliveryTargets` stays the only one.
- **The five test files CORE-128 owns** — `io.test.ts`, `docs.test.ts`,
  `migrate.test.ts`, `store.test.ts`,
  `scripts/antigravity-plugin-config.test.mjs`. New tests go in new files; stop
  and report if one of these must change.
- **`.worktrees/kanmer`, `.worktrees/core-128`, `.worktrees/skill-036`, any
  `verify-*` worktree** — never touched.
