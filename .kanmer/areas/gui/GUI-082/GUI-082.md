## What

Sweep `apps/gui/src/renderer/src/styles.css` (~1,890 lines, one global
stylesheet, no CSS modules) for two related defects:

1. **Dead rules** — selectors that match no markup in any `.tsx`.
2. **Mis-scoped rules** — a rule scoped to one component (`.foo .bar`) whose
   class (`.bar`) is also used by an unrelated component, which therefore gets
   no styling at all while *looking* styled at the call site.

## Why

[[GUI-072]] was exactly this shape, and it shipped as a visible bug: `.check`
was styled only as `.filterbar .check`, so the same markup in Settings
(`Settings.tsx:282`, `:309`, `:513`) and Backlog (`BacklogTable.tsx:147`)
rendered as an unstyled `<label>` — the checkbox stretched to full width and the
label text fell onto the next line. Worse, the scoping rule was **dead**:
`FilterBar.tsx` has had no checkbox since the initial commit, so
`.filterbar .check` had matched nothing, ever. A rule that matches nothing was
the only reason a class name looked accounted for.

GUI-072's research surveyed every `className="check"` in the repo (four sites,
all fixed) and the checkbox-row idiom generally. It did **not** sweep the other
~1,800 lines. That sweep was deliberately kept out of GUI-072 (`open-questions`
Q7) because a one-rule fix should not carry a stylesheet-wide audit's risk
profile — but it was recommended for filing rather than dropping. This is that
filing.

## Approach

- Extract every selector from `styles.css`; for each, check whether the class
  appears in any `.tsx` (`className=`, `class=`, template-literal class
  computations, and the `d === x ? "a" : "b"` conditional shape used in
  `Board.tsx:141`).
- Bucket the results: **dead** (class unused anywhere), **mis-scoped** (class
  used outside the ancestor the rule requires), **fine**.
- Delete the dead. For each mis-scoped rule, decide per case whether to promote
  it to a bare rule (as GUI-072 did for `.check`) or to fix the call site — do
  not blanket-promote, since some component scoping is intentional.
- Known duplicate-idiom cleanup to fold in: `.check` and `.check-row` are two
  names for one thing. GUI-072 deliberately left `.check-row` alone because it
  was the only correctly-rendering row and unifying it there would have turned
  the reference implementation into a regression risk. With `.check` now proven,
  that constraint is gone.

## Verification

- [ ] Every deleted selector shown unused by grep, recorded per rule.
- [ ] Every promoted/rescoped rule re-rendered before and after at each of its
      call sites, dark and light.
- [ ] `npm test`, `npm run typecheck`, `npm run build:ui` green.
- [ ] No visual change at any call site that was already rendering correctly.
