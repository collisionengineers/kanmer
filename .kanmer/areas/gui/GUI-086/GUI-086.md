## What

`apps/gui/src/main/kanmerGit.test.ts` fails intermittently. It spawns **real git
subprocesses** against vitest's default **5 s** timeout, and on Windows it also
hits `EPERM` cleaning up its temp directories.

Two independent agents hit it during the HZN-003 auto run, on unrelated diffs, and
both had to spend real time proving it was not their regression:

- **SKILL-018** — `@kanmer/core` 193/193 clean every run; `@kanmer/gui` timed out
  only under concurrent load from other worktrees. Reran the file alone with
  `--testTimeout=30000` → 7/7 clean.
- **GUI-070** — proved it three ways: its merge commit touches **zero** files under
  `src/main/`; the failure **reproduces at the pre-merge base `fc2045b`**; and the
  file is 7/7 green run alone at a 30 s timeout.

## Why

The cost is not the failure, it is the diagnosis. Each agent that hits this has to
establish it is pre-existing before it can trust its own rail — and the honest way
to do that takes several minutes and three separate checks. That is a tax on every
GUI ticket, paid repeatedly.

The worse failure mode is the one that has not happened yet: an agent that has seen
this flake twice starts treating a red `@kanmer/gui` run as noise, and waves through
a real regression. A test that cries wolf is worse than no test, and this one is
now well-established enough to have taught two agents to expect it.

Note the two causes are different and both need addressing:

- **Timeout under load.** 5 s is generous for a git subprocess on an idle machine
  and far too tight when a dozen worktrees are competing for the disk. The test is
  not wrong; the budget is.
- **Windows `EPERM` on temp-dir cleanup.** A file handle is still open when the
  test tries to remove its scratch directory. GUI-070 hit a related shape at
  closeout: `git worktree remove` failed because a stray `electron.exe` survived
  `child.kill()`, which does not reap Electron's helper processes.

## Approach

- Raise the per-test timeout for this file specifically, rather than globally —
  a global raise hides genuinely slow tests elsewhere.
- Fix the cleanup rather than swallowing its error: find what still holds the
  handle. Retrying `rm` in a loop is a last resort and should be labelled as one.
- Consider whether every case genuinely needs a real git subprocess, or whether
  some can assert against an injected runner. Do not convert them all reflexively
  — the value of this suite is that it exercises real git.
- Do **not** mark it skipped.

## Verification

- [ ] The file passes repeatedly with the rest of the suite running concurrently —
      evidenced by several consecutive full-suite runs under load, not one clean run.
- [ ] Temp directories are actually removed; no `EPERM` and no leftover dirs.
- [ ] The timeout change is scoped to this file, with a comment saying why.
