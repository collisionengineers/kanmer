## Problem

Format-3 ticket documents are stored as folders. A ticket summary can report `docs.research: true` while a bare `get_ticket_doc(id, doc: "research")` returns absent, because that form only reads the conventional index file `research/research.md`.

GUI-102 demonstrates the mismatch: its research exists at `research/portable-connect-integration.md`, but callers cannot discover that path through the MCP surface. This can lead agents to incorrectly conclude a ticket has no research.

## Desired outcome

Make the MCP surface let callers discover the exact document paths present for a ticket, or otherwise make the response to a bare document-type read unambiguous about named documents beneath that folder. Preserve explicit path reads and existing compatibility semantics.

Coordinate with [[MCP-019]] so batch reads can consume the discovered paths without duplicating document-resolution logic.

## Verification

- A ticket with only `research/<named>.md` exposes that exact path through MCP.
- A caller can distinguish “no research files” from “research exists but no `research/research.md` index”.
- GUI-102's `research/portable-connect-integration.md` is discoverable and readable without prior filesystem knowledge.
- Existing explicit nested-path and bare-index reads remain compatible.
