## Ripple effects

- **Callers.** `resolveProjectRoot` has exactly one source caller,
  `packages/mcp-server/src/index.ts:33`. Changing its return type is contained,
  but `projectRoot` is captured by closures throughout that file — `get_status`
  (240), `watchKanmer` (1013), the boot stderr line (1101) — so the refactor from
  module-level `const` to something resolved inside `main()` is the widest
  mechanical edit in the change.
- **Tests.** `apps/gui/src/main/kanmerGit.test.ts` exercises `ensureBoardWorktree`
  and is **not** modified, but it is the best existing reference for building
  real git-worktree fixtures if the plan wants a filesystem-level test rather
  than a purely injected one. `apps/gui/src/main/{providers,mcp-sessions}.test.ts`
  assert on `--root` in generated command lines — unaffected (registration still
  emits `--root`), but grep them before touching anything named `root`.
- **Build artifacts.** `plugins/kanmer/mcp/kanmer-mcp.cjs` must be rebuilt and
  committed in the same change. `dist/` is gitignored (`.gitignore:2`), so it is
  the only artifact in the diff.
- **Docs.** Five prose locations assert the old order (FRD-022 ×2, AGENTS.md,
  README.md, examples/codex-config.toml) plus `root.ts`'s docstring. FRD-022 is
  `status: approved`, so amending it is a governing-doc edit, not a comment fix.
- **Downstream tickets.** [[MCP-011]] (blocked by this) removes the need for the
  manifests to carry `--root` and should land immediately after. [[MCP-012]]
  consumes the `how` field in `get_status` — agree the field name here so it does
  not have to be renamed later. [[MCP-008]]'s Desktop `.mcpb` case is *not* solved
  by discovery; it only inherits the better error message.
- **Verification commands.** `npm run test -w @kanmer/core`, `npm run typecheck`,
  `npm run build`, `npm run plugin:build`, `npm run plugin:check`,
  `npm run smoke:protocol`, and `node packages/mcp-server/src/smoke.mjs`.
- **Falsification evidence** the ticket demands (today's build reporting no board
  from a no-`--root`, cwd-at-repo-root invocation) must be captured **before** the
  fix lands, or it cannot be reproduced afterwards.

## Out of scope

- Changing either plugin manifest — that is [[MCP-011]], and it is deliberately
  sequenced after this so the manifests are fixed against a resolver that works.
- Adding the server-build identity fields to `get_status` — [[MCP-012]]. This
  ticket adds only the *root provenance* field.
- The headless/`.mcpb` install path — [[MCP-008]].
- Validating an explicit `--root`/`KANMER_ROOT` that points at a board-less
  directory. Deliberate: two shipped scripts depend on it being permitted.
- Teaching the GUI to discover a board (`openProject` is always given an explicit
  path). The new core function is available to it, but nothing in
  `apps/gui` is edited.
- Any change to `deriveRepoRoot` or to how `refs` resolve.
- Moving the server bundle out of the install directory — [[MCP-005]].
