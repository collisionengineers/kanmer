## What

Add a standardized GUI-level tunnel manager that can create, configure, start, stop, inspect and remove secure MCP tunnel connections independently for any Kanmer project, including several projects running simultaneously.

## Why

The proven OpenAI tunnel workflow is currently manual and PowerShell-specific. Paths, profiles, keys, health ports, tunnel associations and process lifetime must be managed by the user, which does not scale across projects and makes safe simultaneous operation difficult.

## Approach

- Add per-project tunnel configuration and lifecycle controls to Settings → Connect, with clear separation between project board roots and source roots.
- Support tunnel-client discovery/download/update, runtime-key references without plaintext persistence, tunnel/profile creation, doctor/readiness diagnostics, logs, restart and removal.
- Allocate conflict-free health/admin endpoints and supervise multiple project tunnels concurrently with explicit project identity and status.
- Surface full operational controls and failures while preserving outbound-only networking, least privilege, secret redaction and provider-neutral extension points.
- Reconcile tunnel processes with app startup, project close and Kanmer updates without silently interrupting active remote work.

## Verification

- [ ] A user can configure and connect a new project without constructing command lines or editing YAML.
- [ ] Two or more projects run concurrently and ChatGPT reaches only the board selected for each tunnel/app.
- [ ] Credentials never enter project files, logs or UI diagnostics; revoke/reconfigure and failure recovery are testable.
- [ ] Install, update, restart, stop, health, logs and cleanup are controllable and accurately represented in the GUI.
