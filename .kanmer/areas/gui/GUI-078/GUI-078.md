## What

`packages/ui/src/demo.tsx` does not typecheck — **12 errors**, all of them the
v2 core API. Bring it up to format 3.

## Why

`@kanmer/ui` is the design system packaged for Claude Design. It has a
`typecheck` script and **nothing has ever run it**: `build:ui` exists, no rail
calls it, and tsup does not typecheck. So the errors have been there since
format 3 landed, invisible.

Found by [[GUI-067]], which adds a root aggregate typecheck and cannot ship
while a workspace it covers is red.

`demo.tsx` is not scaffolding that could be excluded — `index.ts:75-79` exports
`demoBoard`, `demoItems`, `demoActivity` and `KanmerProviderProps` from it. It is
part of the package's public surface, so a consumer importing the demo provider
gets types that do not match the core it is demonstrating.

## The errors, by cause

```
demo.tsx(318,27) (318,42) (347,33) (414,36) (521,23) (523,25)
    'board.statuses' is possibly 'undefined'
demo.tsx(349,25)  Property 'priority' does not exist on type 'CreateItemInput'
demo.tsx(429,19)  '"area"' and '"status"' have no overlap
demo.tsx(430,38)  ... must have a '[Symbol.iterator]()' method
demo.tsx(463,32)  BoardMigrationReport is missing v2, backfill, v3
demo.tsx(492,5)   TicketDocsInfo is missing counts, references
demo.tsx(507,30)  DocModel is missing docTypes, gateExemptFolders, boundaries, profiles, and 2 more
```

Every one is the same story: format 3 removed `statuses` (ADR-0002) and
`priority` (ADR-0006), and reshaped the migration, docs and doc-model payloads.
The demo was written against the shapes that existed before.

The stage vocabulary is stale in ways the compiler cannot see, which is the part
worth being careful about:

```ts
if (it && !(docs[id]?.plan) && it.status === "planning")
  ... out[s.id] = ["plan.md required before leaving Planning"]
```

`planning` is not a format-3 stage. Fixing only the type errors would leave a
demo that compiles and lies.

## Approach

- Fix the shapes against `packages/core/src/types.ts`, not against what makes the
  compiler quiet. A cast to `any` here would ship wrong types to a design-system
  consumer, which is worse than the current state.
- Replace the seven-stage vocabulary with the six fixed stages, and the
  hardcoded gate strings with something profile-shaped — or drop the fake gate
  logic entirely if the demo does not need it. `getGateStatus`'s
  `board.statuses.slice(3)` is a magic index into a list that no longer exists.
- Check the rest of `packages/ui/src` while here: nothing has typechecked it, so
  `demo.tsx` is unlikely to be the only stale thing.
- Verify the demo still *runs*, not merely compiles.

## Verification

- [ ] `npm run typecheck -w @kanmer/ui` clean.
- [ ] No `any` or `as unknown as` introduced to silence an error — each fix
      matches the real shape in `packages/core/src/types.ts`.
- [ ] No format-2 vocabulary left: no `statuses`, no `priority`, no `planning` /
      `researching`, no `plan.md required before leaving Planning`.
- [ ] `npm run build:ui` still produces `dist/index.js`, `index.d.ts`, `index.css`.
- [ ] The demo renders — a design system whose demo compiles but throws is not
      fixed.
