## What

Provide a GUI-managed lifecycle for OpenAI Secure MCP Tunnel profiles that launch Kanmer's existing stdio MCP server.

## Why

The current manual workflow is PowerShell- and profile-driven. It is distinct from the Cloudflare named-tunnel HTTP adapter and must not share its lifecycle, credential model or dependency graph.

## Approach

- Use the documented OpenAI tunnel client/profile model from [[DOC-010]].
- Keep runtime API-key references out of project files, logs and board documents.
- Manage one OpenAI tunnel/profile/app per project, including health-port conflicts, start/stop/restart and Kanmer-update recovery.
- Do not implement Cloudflare Tunnel, Access, Worker-hosted MCP, or a public HTTP relay in this ticket.

## Verification

- [ ] Two project profiles can run without colliding and select the intended board.
- [ ] Runtime keys and tunnel identifiers remain outside repository-tracked state and diagnostics.
- [ ] The GUI reports lifecycle failures and restart requirements accurately.
