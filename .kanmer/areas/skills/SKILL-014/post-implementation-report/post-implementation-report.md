**The rule applied, since "every skill names its successor" cannot be literal:**
a skill passes if it has an ordered workflow — an explicit `## Workflow` section
**or** numbered `## N.` headings, which four skills already used as their
structure — and ends by naming what comes next. Duplicating a numbered list above
sections that already *are* the numbered steps would be the restatement FRD-023
R1 warns about, so those four keep their structure and gain only the ending.

Service skills (`tickets`, `docs`, `report`) name their **callers and where
control returns**; `closeout` says the pipeline ends. That answers the need the
ticket states — "no reliable way to know what precedes or follows" — without
fabricating successors that do not exist.
