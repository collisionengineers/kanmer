Not everything attached to a ticket is a document. Two other things live beside
them, and neither can ever tick a box.

## Attachments

Scroll down the Ticket tab and you will find a section headed **Attachments**,
with the hint *inputs to the work — never satisfy a document gate*.

This is where you put what you are handing the work: a mockup, an exported
design, a log from the failure you are chasing, a schema, a screenshot of the
bug, a spreadsheet somebody sent you. Anything, any file type.

Add one by **dragging it onto the section**, or with the **Add files…** button
and a normal file picker. Click a listed file to open it in whatever your
system uses for that type. Removing takes two clicks — Kanmer asks before
deleting, because these are often the only copy.

If you add a file whose name is already there, Kanmer keeps both and numbers the
new one. Nothing is overwritten silently.

Attachments live in the ticket's own folder, so they travel with it, they are
versioned with your board, and **your agents can read them**. That last one is
the real reason the section exists: "here is the mockup, build this" is a
sentence you can now actually mean.

## Scratch

Scratch is the agent's notepad. When an agent is part-way through something and
wants to leave itself a note — a half-finished trace, a list of files it has
already checked, a hypothesis it wants to come back to — it appends to scratch
rather than putting it in a document that somebody will later read as a finding.

Scratch does not appear as a tab in the editor. It is deliberately quiet: notes
in progress are not deliverables, and a notepad promoted to a document is just
noise with a filename. You will see scratch in the ticket's folder if you go
looking, and agents can read each other's.

## Neither one satisfies a gate

This is enforced, not merely discouraged. A ticket that owes a research document
still owes it after you attach forty files; a ticket that owes a plan is not
unblocked by an agent writing a very long scratch note.

That is deliberate, and it is worth being clear about why. An attachment is an
**input** — it is what you were given. Scratch is **working**, not conclusions.
A gate is asking whether somebody has done the thinking and written it down, and
neither of those things is evidence that they have. If gates accepted them, the
easiest way to pass would be to attach the thing you were sent, which is exactly
the behaviour the gates exist to prevent.

If you find yourself wanting an attachment to count, the honest move is usually
to change the profile — see **Profiles: what a ticket owes** — rather than to
find a way around it.
