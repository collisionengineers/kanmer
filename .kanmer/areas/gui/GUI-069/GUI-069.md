## What

The board renders **BACKLOG after DONE**. Backlog is work not started; it
belongs at the left-hand end, before Preparing.

## Why

A kanban board reads left-to-right as flow. Putting the not-started column past
the finished one inverts that, and it is the first thing you see on opening the
app.

Root cause is an accident, not a decision — the column is not supposed to be
there at all. `Board.tsx:115-120` deliberately removes it:

```ts
STAGES.filter((s) => s.id !== "backlog")
```

with a comment citing FRD-011. But that filtered list is then passed through
`mergeColumns` (`Board.tsx:29-33`), whose job is to append any status found on
items that has no configured column:

```ts
const extra = [...new Set(present)].filter((id) => id && !ids.has(id));
return [...defined, ...extra.map((id) => ({ id, name: id }))];
```

So the six backlog tickets resurrect the column through the **unknown-status
fallback**, and that fallback appends at the end. The fallback exists for a
status nobody configured; `backlog` is a status that was configured and then
deliberately excluded. `mergeColumns` cannot tell those two cases apart.

That is also why the column header reads as a raw id rather than a styled
stage — it is being treated as an unknown value.

## Approach

- Decide what the board should actually do with backlog tickets, then make the
  code say it. Two coherent answers: show Backlog as a real first column, or
  genuinely exclude it. Silently re-adding it last is neither.
- Given [[GUI-070]] wants the separate Backlog view gone, a first column is the
  likely answer — but the two tickets must agree, and this one lands first so
  there is never a moment with no way to see backlog tickets.
- `mergeColumns` needs to distinguish "unknown status" from "known status,
  deliberately hidden". Whatever the decision, that ambiguity is the defect.

## Verification

- [x] With backlog tickets present, Backlog renders **first**, styled like every
      other stage, with its stage colour and name from `STAGES`.
- [x] With zero backlog tickets, the board still looks right — no empty column
      appearing and disappearing as the count crosses zero.
- [x] A genuinely unknown status on an item still gets its fallback column, and
      still appears last.

## Outcome

Shipped in **PR [#38](https://github.com/collisionengineers/kanmer/pull/38)**,
squash-merged to `main` as `488797d` on 2026-08-16. Five files, one commit.

The board now renders all six stages from `UI_STAGES`, so **Backlog is the first
column**, in stage order, with its real stage name and the same `.col-head`
treatment as every other column. The root defect was fixed rather than the
symptom: `mergeColumns` moved out of `Board.tsx` into `lib/board.ts` and gained a
third argument — the statuses the caller *knows about*, kept distinct from the
columns it *renders* — so a known-but-hidden status stays hidden while a
genuinely unknown one still earns its trailing fallback column. Deleting the
`.filter(...)` alone would have left the board one hidden stage away from the
identical bug.

It moved to `lib/board.ts` for a concrete reason: `apps/gui` has **no
component-test harness**, so a module-private helper in `Board.tsx` could not be
asserted at all. Eight new cases in `lib/board.test.ts` turn all three
verification criteria into assertions; two of them fail against the old
implementation. `mergeColumns` was also added to the `@kanmer/ui` barrel.

### Shipped differently than planned

- **The plan expected to amend `FRD-007` B4; it amends no FRD.** During
  scheduling, single ownership won: B4 is one sentence whose *both halves*
  reverse — this ticket falsifies the first, GUI-070 the second — so splitting it
  across two branches would be a guaranteed same-line conflict.
- **One unplanned line:** the now-unused `BoardColumn` type import was dropped
  from `Board.tsx`. Mechanical — the moved function was its only consumer there,
  and the GUI typecheck rejects an unused import.
- **Correction to research:** `packages/ui` is **tracked** in git (21 files); the
  "untracked" note was true when research was written and had gone stale.
