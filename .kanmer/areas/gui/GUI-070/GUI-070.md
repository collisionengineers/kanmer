## What

Drop the **Backlog** tab from the view nav. Backlog belongs on the board as a
column; a second place to look at the same tickets is not earning its keep.

## Why

User's call, and it reverses a shipped decision — which is worth stating plainly
rather than quietly deleting the code.

FRD-011's argument was: *"a kanban column is for work in flight; a backlog is a
queue you scan, sort and triage, which a column cannot do."* That reasoning
produced `BacklogTable` — a sortable, windowed table with **bulk actions**
(move, group, archive) and a bulk-move that reports which tickets could not go
and why.

**Deleting the view deletes those affordances.** That is the real cost and this
ticket should not pretend otherwise. Two honest options:

1. Accept the loss — bulk triage is rare enough that the second view is not
   worth the permanent split-brain of two places showing the same tickets.
2. Move what matters onto the board — multi-select and a context-menu bulk move
   in the Backlog column — and then delete the view.

Pick one deliberately. Option 1 is smaller and matches "this isn't needed";
option 2 keeps the capability. Do not half-do it and discover in a month that
bulk archive is gone.

**FRD-011 must be amended either way** — its premise no longer holds. Authorized
by the user in this request; record it in the plan's Governing docs section so
review can check the claim.

## Approach

- Blocked by [[GUI-069]]: the column must exist before the view goes, or there
  is a window with no way to see backlog tickets at all.
- Remove the `backlog` entry from `View` / `VIEW_LABELS` (`App.tsx:49-56`) and
  the `BacklogTable` branch (`:1184-1186`). Note the Ctrl+N view shortcut is
  derived from `VIEW_LABELS` on purpose (`App.tsx:931-938`) — that comment says
  a hardcoded list "went stale the moment the Backlog view was added", so
  deriving should absorb the removal for free. Verify it does.
- Decide `BacklogTable.tsx` and `windowedRows.ts`: delete, or keep if the board
  column reuses them. Dead files left behind are their own bug.

merged 2026-08-16 as `2f06713`.** Option 1 taken as the operator settled it: the
loss was accepted, nothing was ported.

Deleted: the Backlog tab and its render branch, `BacklogTable.tsx` (257 lines),
`windowedRows.ts` (79) and its 13-case suite (111), the 52-line CSS block, the
two `@kanmer/ui` re-exports, and the generated manual chapter. `Ctrl+1…4` became
`Ctrl+1…3`; the handler needed no edit, because it derives its targets from
`VIEW_LABELS` — the removal renumbered for free, which was the prediction the

(Ctrl+1/2/3 map correctly, **Ctrl+4 is now inert**).

**Bulk triage is gone, not relocated** — multi-select, bulk move / archive /
add-to-group, and the per-ticket failure report. Recorded in three governing
documents so the loss is discoverable from any of them, with the reopen path
being a new ticket against the board column rather than a reinstatement of the
view.
