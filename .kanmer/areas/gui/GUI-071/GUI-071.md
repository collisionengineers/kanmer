## What

The nav reads **Board 111 / Backlog 111** — the same number on both, and 111 is
every non-archived ticket including the 105 that are Done. The Backlog tab
should read 6.

> **Amended 2026-08-16 by [[GUI-070]].** The Backlog *view* is gone — its tab,
> its render branch and `BacklogTable` were deleted, and Backlog is now only the
> board's first column. The nav is Board / Standup / Archived. The **defect this
> ticket exists for is unchanged**: one shared count expression serves every tab
> that is not Archived, so Board still reads a total dominated by finished work.
> The Backlog tab is simply no longer one of the tabs getting a wrong number.

## Why

`App.tsx:1067-1072` uses one expression for every tab that is not Archived:

```tsx
{v === "archived"
  ? items.filter((i) => i.archived).length
  : items.filter((i) => i.type === "ticket" && !i.archived).length}
```

There is no per-view branch, so the count does not depend on `v` at all beyond
the archived special case. Backlog gets the board total; Board gets a total that
includes everything already finished.

A count next to a tab is a promise about what is behind the tab. Both tabs
currently break that promise, and the Backlog one breaks it by a factor of ~18.

Second question worth settling while here: **should the Board count include
Done?** 105 of the 111 are finished. A board count that is dominated by
completed work tells you nothing about what is in flight. Arguably Board should
count unfinished tickets, which is the number a person actually wants.

## Approach

- Give each view its own count, derived from the same predicate the view uses to
  filter — the count and the contents must come from one source, or they drift
  apart again the next time a filter changes.
- Decide the Board count's meaning explicitly (all non-archived vs. not-done)
  and write it down; "111" being technically true is what made this survive.
- [[GUI-070]] has landed, so there are two counted tabs, not three: Board and
  Archived, with Standup uncounted. The shared-expression bug is the defect, not
  the Backlog tab.

## Verification

- [x] Board tab count matches the documented meaning, asserted in a test so the
      next filter change cannot silently break it.
- [x] Archived count unchanged.
- [x] Counts update live when a ticket moves between stages.

## Outcome

**Shipped** in PR #43's successor, [PR #53](https://github.com/collisionengineers/kanmer/pull/53),
squash-merged as `5cab894`. Evidence in `proof`.

The view rule now lives once, in `apps/gui/src/renderer/src/lib/views.ts`, as a
`Record<View, ViewSpec>` keying each view's **label**, the **items it renders**
and **whether it has a badge** together — so a view added later does not compile
until it says what it contains, and its badge cannot drift from its contents.
The tab strip, Ctrl+1…3, `allViewItems`, the `FilterBar` facet set and the empty
states all derive from it. Three inline copies of the rule survived GUI-070 and
all three are gone; the fourth went with `BacklogTable`.

**No printed number changed, and that is the finding.** Post-GUI-070 the old
expression's two branches coincide exactly with the two surviving counted views'
predicates, so the badges were already right — by coincidence, not construction.
The expression branched only on `archived` and was never a function of the view;
it agreed with the views only because Backlog, the one view whose predicate
differed, had just been deleted. A fourth view would have ended the coincidence
silently. What shipped is the missing branch, an assertion that holds for views
nobody has written yet, and the meaning written down.

**Both open decisions are now in the FRD**, which is where the ticket said the
problem started. `FRD-019` R5 listed the views and was **silent on badges**;
it gains R5a (a badge counts everything in that view, Done included for Board,
non-ticket items included for Archived because it renders them), R5b (badges
ignore the active filter while the board's per-column counts respond to it —
observed at 155 in the badge against 2 across the columns, both correct), and
R5c (one source, in `lib/views.ts`, under test).

Second question in *Why* — "should the Board count include Done?" — answered by
the operator on 2026-08-16: **no change, all non-archived tickets**. Recorded in
`open-questions` Q1.
