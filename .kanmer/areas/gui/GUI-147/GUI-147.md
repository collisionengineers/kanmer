## Why
Observed after installing v0.4.0 on 2026-09-01/02. `stageClaudeMarketplaceRoot()` in `apps/gui/src/main/connect.ts` copies the marketplace into `mkdtemp(kanmer-claude-marketplace-*)`, runs `claude plugin marketplace add <staged>` then `claude plugin install kanmer@kanmer`, and finally `rm`s the staged directory (line ~603). Two consequences:
1. Claude Code records a **directory** marketplace whose `installLocation` *is* the staged path. Once it is deleted, `/reload-plugins` and every new session report `Marketplace kanmer failed to load: cache-miss` and the plugin (skills + `plugin:kanmer:kanmer` MCP server) fails to load.
2. `claude plugin install` is a no-op when the plugin is already installed, so the cached plugin stayed at **0.3.12** (`~/.claude/plugins/cache/kanmer/kanmer/0.3.12`) after the 0.4.0 install; the marketplace `lastUpdated` moved to 23:32Z but the plugin did not. Connect reported success.

Net effect: Claude Code kept running the 0.3.12 skills and server against a board promoted to 0.4.0 — exactly the stale-control-plane condition HZN-008 exists to prevent.

## Interim repair applied by hand (2026-09-02)
Staged a persistent copy at `%LOCALAPPDATA%\Kanmer\claude-marketplace\` (`.claude-plugin`, `.agents`, `plugins/kanmer` with `KANMER_BOARD_BRANCH` bound), `claude plugin marketplace rm kanmer`, `marketplace add <dir>`, `plugin install kanmer@kanmer -s user -y` → `kanmer@kanmer 0.4.0 enabled`. The GUI's next Connect will overwrite this with the temp-dir form again unless this ticket lands.

## Outcome
- Stage the Claude marketplace in a **stable, installer-owned** location (e.g. under `%LOCALAPPDATA%\Kanmer\`), refreshed on every Connect, never deleted while the marketplace is registered; disconnect removes the marketplace registration first.
- After `marketplace add`, run `claude plugin marketplace update kanmer` and `claude plugin update kanmer@kanmer` (or uninstall/install) so an existing install moves to the bundled version; verify with `claude plugin list` that the reported version equals the bundled `plugin.json` version, and fail Connect (with the pasteable fallback) when it does not.
- Surface the installed plugin version in the GUI's staleness read next to the skills stamp.
