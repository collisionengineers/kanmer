## What

[[MCP-007]] shipped `isLinkedWorktree` in `scripts/check-plugin-sync.mjs` and
proved both branches with a **hand-run command log**, because at planning time
nothing in the repo tested `scripts/`.

That premise expired mid-ticket: [[GUI-066]] landed
`"test:scripts": "node --test \"scripts/*.test.mjs\""`, chained onto root `npm test`.
So the guard now has somewhere to live as a real test. Put it there.

## Why

A hand-run log proves the guard worked once. It does not re-run.

`plugin:check` is **step 1 of the release gate**, and this guard is the thing
standing between a worktree-built bundle and a release that validates it as
correct — which is exactly the failure that shipped a stale bundle and prompted
MCP-007. If the guard silently stops firing, the defect returns and nothing says
so. That is the same shape as the SKILL-011 failure the operator cited when
refusing an escape hatch: a check that reports OK when it cannot be true.

Both branches are cheap to test and neither needs a real release:

- `--git-dir` !== `--git-common-dir` (the linked-worktree case)
- `statSync(root/.git).isFile()` (the git-off-PATH fallback)
- a non-git directory must stay **silent** and must NOT refuse — MCP-007
  exercised this and it is the case most likely to regress into a false refusal

## Approach

- Extract `isLinkedWorktree` if it is not already callable in isolation, keeping
  `scripts/` dependency-free — that constraint is why GUI-066 chose `node:test`
  over vitest, and it still holds.
- Test against fixture directories rather than the repo's own worktrees, so the
  test does not depend on which worktrees happen to exist while it runs.
- Include the false-refusal case explicitly.

## Verification

- [ ] Both detection branches and the non-git case are asserted by
      `npm run test:scripts`.
- [ ] The tests fail if the guard is disabled — demonstrated, not assumed.
- [ ] `scripts/` gains no dependency.
