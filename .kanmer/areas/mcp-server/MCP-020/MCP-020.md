## What

Expose Kanmer's background-agent dispatch capability through an explicit MCP surface so authorized remote clients, including tunnel-connected ChatGPT apps, can start, inspect and cancel ticket-scoped work.

## Why

Dispatch currently exists only behind Electron IPC. Remote MCP clients can manage tickets but cannot ask the local Kanmer host to launch an installed agent CLI, leaving a material capability gap between local GUI and remote use.

## Approach

- Define narrowly scoped dispatch, status/list and cancellation tools over the existing dispatch engine.
- Bind every request to the server's configured project and a declared provider/task; never accept arbitrary executables, arguments or unrestricted prompts.
- Add approval, provider allowlisting, concurrency controls, audit/activity attribution, lifecycle/error reporting and secure remote-host behavior.
- Keep the GUI and MCP surfaces on one dispatch contract rather than duplicating process supervision.

## Verification

- [x] An authorized MCP client can dispatch one named task for one ticket, observe its state and cancel it.
- [x] Cross-project, arbitrary-process, duplicate-dispatch and unauthorized/destructive cases are refused and tested.
- [x] Tool annotations, skills/tool reference, protocol smoke tests and GUI dispatch behavior stay synchronized.
