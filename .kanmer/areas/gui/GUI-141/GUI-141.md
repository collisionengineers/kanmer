The shipped GUI uses obsolete tunnel-client init/doctor/run commands and owns a child process. tunnel-client 0.0.11 instead exposes a persistent managed-runtime interface: runtimes connect/status/stop/rm. This mismatch makes the ChatGPT connector fail before any request reaches Kanmer, while the manually created kanmer-board runtime remains healthy. Correct FRD-026 and the Windows GUI lifecycle to manage one runtime alias per canonical project, surface truthful runtime status, avoid presenting Cloudflare bearer access as ChatGPT OAuth, and prove a packaged ChatGPT connection reaches Kanmer.
