Observed 2026-09-03 while running `npm run verify` for GUI-149. `packages/mcp-server/src/http.test.mjs` "project resolution fails before binding and leaves no listener" spawns a cold Node from `os.tmpdir()` and expects `host.start()` to throw "no Kanmer board found". On this machine it instead printed `UNEXPECTED_READY` and hung until the 30 s `spawnSync` timeout, failing the rail three times.

Cause: `C:\Users\Alex\.kanmer\` exists and contains only `endpoints.json` (the remote-access endpoint registry, written 2026-09-03 09:50). ADR-0012 discovery walks up from `%TEMP%` (`C:\Users\Alex\AppData\Local\Temp`) to `C:\Users\Alex` and accepts any directory named `.kanmer` as a board root, so the HTTP host "found" a board with no `data/board.yml`, started, and the child never exited.

Two things worth a look: (1) discovery should probably not accept a `.kanmer` that holds only an endpoint registry (or the registry should live elsewhere than a directory name that means "board"); (2) the test is environment-sensitive — it assumes nothing above `os.tmpdir()` looks like a board. Workaround used for GUI-149: run verify with `TMP`/`TEMP` pointed outside the home folder. Nothing in `~/.kanmer` was deleted.
