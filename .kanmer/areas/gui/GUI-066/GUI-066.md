## What

`scripts/release.mjs` ends by checking that `latest.yml` is fetchable. Make it
check the installer and the blockmap too, and fail the release if any expected
asset is missing.

## Why

**Three consecutive releases uploaded incompletely**, each time with
electron-builder logging a successful upload:

| Release | What was missing |
|---|---|
| 0.3.0 | `Kanmer-Setup-0.3.0.exe.blockmap` |
| 0.3.1 | `Kanmer-Setup-0.3.1.exe` **and** `latest.yml` |
| 0.3.2 | `latest.yml` |

Every one needed a manual re-publish. This is not a fluke — it is the normal
behaviour of this publish path and it must be assumed rather than hoped against.

The existing `latest.yml` check is the only reason none of these shipped broken,
and it caught only two of the three. **0.3.0 passed the gate while missing its
blockmap**, which is the quiet failure: `Provider.getBlockMapFiles` derives the
*previous* release's blockmap URL by string-substituting the version, so a
missing old blockmap silently costs every client on that version a full ~78 MB
download instead of a differential one. Nobody notices; everyone pays.

The 0.3.1 case is the loud one: `/releases/latest` pointed at a release whose
manifest 404'd. Every installed client would have failed its update check.

## Approach

- Extend the final verification to assert all three assets exist on the release,
  with plausible sizes — an `.exe` of a few hundred bytes is a failed upload
  that returned 200.
- Given a 3-for-3 failure rate, consider **re-publishing automatically** on a
  detected gap rather than only refusing, then re-verifying. A refusal after the
  tag has been pushed leaves `/releases/latest` broken until a human intervenes,
  which is exactly the state 0.3.1 was in.
- Worth checking whether `EP_GH_IGNORE_TIME=true` (needed for both manual
  re-publishes) should just be set by the script.
- Backfilling v0.3.0's blockmap is a separate question — it needs a rebuild of
  that version. Decide, don't drift.

## Verification

- [ ] Simulate a missing asset (delete one from a draft release) and confirm the
      script fails or repairs rather than reporting success.
- [ ] A clean release still passes without manual intervention.
- [ ] The next real release completes in one run — no manual
      `npx electron-builder --publish always` second pass.
