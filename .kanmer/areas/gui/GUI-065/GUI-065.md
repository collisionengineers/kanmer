## What

With no project open, the app gives no way to see or act on an available update.
Render the update banner, toasts and the restart prompt on the welcome screen
too.

## Why

`apps/gui/src/renderer/src/App.tsx:1015` returns early:

```tsx
if (!root || !board) {
  return <Welcome … />;
}
```

Everything that surfaces an update sits *below* that return — the banner at
`:1112`, the toast stack, and the "Restart and update" prompt at `:1371`. The
updater itself is app-global and runs fine (its own comment at `:452` says so),
and **Help → Check for Updates…** is not gated (`main/index.ts:328-331`). So the
check runs, the download happens, and the result renders into a subtree the
welcome screen never mounts. The user sees nothing and concludes updating only
works inside a project.

This is the first screen after launch and the most likely moment someone updates
— it is the worst place to hide it.

## Approach

- Lift the update surface (`lib/update.ts` → `updateSurface`) above the `!root`
  early return so both branches render it, rather than duplicating the markup.
- The restart prompt carries the MCP-session warning (`restartWarning`); keep
  that intact on the welcome path — with no project open there is usually
  nothing to lose, but the probe is app-wide, not project-scoped.
- Check `Welcome.tsx` has somewhere sane to put a banner without shifting the
  recents list under the cursor.

## Verification

- [ ] Launch with no project open against a feed offering a newer version — the
      banner appears on the welcome screen and "Restart and update" works.
- [ ] Help → Check for Updates… on the welcome screen produces a visible result
      in both the up-to-date and update-available cases.
- [ ] In-project behaviour is unchanged.
