## Deviations from the plan
- **`plugins/kanmer/mcp/kanmer-mcp.cjs` was regenerated** although the plan listed `plugins/kanmer/**` under "Do not modify". It is the committed build artifact of the server, and `mcpb:check` (part of `npm run verify`) fails when it differs from a fresh build; changing `packages/core/src/staleness.ts` therefore requires `npm run plugin:build`. Built inside the worktree, which has its own `node_modules` with `@kanmer/core` symlinked to the worktree's `packages/core` (checked: the bundle contains `isLegacyLauncherDescriptor` / `PORTABLE_LAUNCHER_COMMAND`, so it is not main's core — the §8 gotcha 8 failure mode). No descriptor, manifest or skill under `plugins/kanmer` changed.
- AGENTS.md §8 gotcha 4 (line ~651) also said project registrations "may still invoke the install-root `Kanmer.exe` directly"; corrected alongside the planned gotcha rewrite.
- `apps/gui/src/main/index.sync.test.ts` and `apps/gui/src/renderer/src/manual/chapters.generated.ts` were not in the plan's file list; both were required (the sync caller test pinned the Electron env shape; the manual is generated from the doc I edited). Recorded in `files.md`.
- `isLegacyLauncherDescriptor` judges **absolute** `Kanmer.exe`/`kanmer-mcp.cjs` paths only, narrower than the plan's "names `kanmer-mcp.cjs`", so an existing core test (`node kanmer-mcp.cjs` with no `--root` is not stale) keeps its meaning.
- The staleness message for legacy `.codex/config.toml` changed wording (shared message for the three hosts); the codex tests assert `state` only and still pass.
- Plan Step 3 listed a symlink-refusal test for `ensureConnectIgnore`; not added — the moved helper's refusal is already covered by `kanmerGit.test.ts` (two assertions, message generalised to "Refusing symlinked ignore path"), and `ensureConnectIgnore` converts any throw into a note, which the ok-path tests exercise.
- `.gitignore` chosen over `.git/info/exclude` (plan default), consistent with `.kanmer/` / `.worktrees/`.
