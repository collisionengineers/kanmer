## What

Record the current Cloudflare remote-access boundary in the roadmap and Remote Access epic context.

## Why

Cloudflare has two deliberately limited roles in this release: `cloudflared` is the named-tunnel adapter, and a disposable Worker is only the external client used by integration verification. This must not be confused with Cloudflare Access, a hosted Worker MCP server, a proxy, or a public relay.

## Approach

- Update the Remote Access epic context and `MASTERPLAN.md` to state Cloudflare Tunnel + Kanmer bearer only.
- Preserve the OpenAI Secure MCP Tunnel as an independent, OpenAI-managed stdio path.
- Mark Cloudflare Access and Cloudflare Workers-hosted Kanmer as deferred; a future hosted mode requires a new ADR and ticket set.
- Keep provider account, DNS, credential and executable lifecycle operator-owned.

## Verification

- [ ] Epic context and roadmap identify the two Cloudflare roles and their exclusions.
- [ ] FRD-025/ADR-0017 terminology remains consistent with the retained local-board architecture.
