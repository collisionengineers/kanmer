## What

Extend the existing multi-project GUI surface to present project registry health, endpoint binding, policy, sync and active controller/workspace state without creating a second board.

## Why

Operators need a concise view of several independently governed projects while mutations remain scoped to the selected project.

## Approach

- Reuse the named registry and current selected-project model.
- Present read-only cross-project health and explicit project selection before actions.
- Avoid cross-project transaction controls or a global backlog.

## Verification

- [ ] GUI tests show two projects with distinct health and prevent accidental action against the non-selected project.
