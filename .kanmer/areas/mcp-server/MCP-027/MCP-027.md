## What

Provide one diagnosis surface distinguishing Cloudflare tunnel/configuration failure, local HTTP-host failure, Kanmer bearer failure, and board/project failure: a CLI (`node …/doctor.mjs --json` or `kanmer tunnel doctor`) plus a connector block consumable by the GUI. Never silently reconnect to a different board.

## Why

A public hostname can fail before an MCP request reaches Kanmer. The doctor must show whether the failure is executable/version, generated ingress, hostname-to-loopback mapping, tunnel readiness, local origin, bearer, or board identity.

## Approach

- Validate the selected cloudflared executable/version and generated ingress using exact-host validation/rule checks.
- Check the loopback listener, negative/positive bearer outcomes, expected project identity and remote tool policy.
- Report Cloudflare-specific configuration/readiness failures separately from local host, bearer and board failures; do not implement Cloudflare Access, cookies, service tokens or identity diagnostics.

## Verification

- [ ] Doctor classifies invalid ingress, tunnel unavailable, origin unavailable, invalid bearer, wrong project and healthy remote MCP without secrets in output.
