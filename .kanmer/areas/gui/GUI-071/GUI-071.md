## What

The nav reads **Board 111 / Backlog 111** — the same number on both, and 111 is
every non-archived ticket including the 105 that are Done. The Backlog tab
should read 6.

> **Amended 2026-08-16 by [[GUI-070]].** The Backlog *view* is gone — its tab,
> its render branch and `BacklogTable` were deleted, and Backlog is now only the
> board's first column. The nav is Board / Standup / Archived. The **defect this
> ticket exists for is unchanged**: one shared count expression serves every tab
> that is not Archived, so Board still reads a total dominated by finished work.
> The Backlog tab is simply no longer one of the tabs getting a wrong number.

## Why

`App.tsx:1067-1072` uses one expression for every tab that is not Archived:

```tsx
{v === "archived"
  ? items.filter((i) => i.archived).length
  : items.filter((i) => i.type === "ticket" && !i.archived).length}
```

There is no per-view branch, so the count does not depend on `v` at all beyond
the archived special case. Backlog gets the board total; Board gets a total that
includes everything already finished.

A count next to a tab is a promise about what is behind the tab. Both tabs
currently break that promise, and the Backlog one breaks it by a factor of ~18.

Second question worth settling while here: **should the Board count include
Done?** 105 of the 111 are finished. A board count that is dominated by
completed work tells you nothing about what is in flight. Arguably Board should
count unfinished tickets, which is the number a person actually wants.

## Approach

- Give each view its own count, derived from the same predicate the view uses to
  filter — the count and the contents must come from one source, or they drift
  apart again the next time a filter changes.
- Decide the Board count's meaning explicitly (all non-archived vs. not-done)
  and write it down; "111" being technically true is what made this survive.
- [[GUI-070]] has landed, so there are two counted tabs, not three: Board and
  Archived, with Standup uncounted. The shared-expression bug is the defect, not
  the Backlog tab.

## Verification

- [ ] Board tab count matches the documented meaning, asserted in a test so the
      next filter change cannot silently break it.
- [ ] Archived count unchanged.
- [ ] Counts update live when a ticket moves between stages.
