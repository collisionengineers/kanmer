## What

Desktop push notifications for ticket document changes (e.g. "research updated") should name the ticket they refer to and use normal title casing, and the notification's grey background should be re-themed to match the app.

## Why

Screenshot attached by the user shows a native toast reading just "research updated" — lower case, generic, and with no indication of which ticket the change belongs to. That's the fallback wording in `flushToasts()` (`apps/gui/src/main/index.ts`), which fires when the batched toast `key` is a document type (e.g. `research`) rather than a ticket id, so the `store.getItem(key)` lookup in the ticket-id branch never resolves and the title falls back to `` `${key} ${event} updated` ``. The intended path (same function) already builds a proper `` `${key} — ${stage}` `` title with the item's own title as the body when `key` is a ticket id — this only needs to also work for doc-level events. Separately, the notification chrome is plain grey and doesn't match Kanmer's theme.

## Approach

- [ ] Research phase: trace why doc-update events reach `flushToasts` with a doc-type key instead of the owning ticket id (see `docs/plans/kanmer-v2/ultrareview-2026-08-14/toastkey-hardcoded-docs.md` for prior related notes), and confirm whether OS-native `Notification` styling can be themed at all on Windows/macOS or whether this needs an in-app toast instead.
- [ ] Rework the doc-update toast branch to resolve the owning ticket and render `` `${ticketId} — ${stage}` `` (or similar) with normal casing, consistent with the ticket-update path.
- [ ] Address the grey background so notification styling matches the Kanmer theme, within whatever constraints native notifications impose.

## Verification

- [ ] Update a ticket's research/plan/checklist doc and confirm the resulting toast names the ticket id, not just the doc type, with proper casing.
- [ ] Visual check that the notification no longer reads as plain grey / mismatched theme.
