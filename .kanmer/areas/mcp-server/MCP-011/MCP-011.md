## What

`plugins/kanmer/mcp/claude.mcp.json` and `plugins/kanmer/.mcp.json` both
register:

```json
{ "command": "node", "args": ["${PLUGIN_ROOT}/mcp/kanmer-mcp.cjs"] }
```

Three defects in two small files.

## Why

1. **No `--root`.** Falls back to cwd, which cannot find a worktree board — see
   [[MCP-010]]. This is what makes a marketplace install report an empty board.
2. **`"command": "node"` reintroduces the Node-on-PATH dependency** that
   `connect.ts:51` deliberately avoids by launching `process.execPath` with
   `ELECTRON_RUN_AS_NODE=1`. Two install paths, two different runtime
   assumptions, one of them undocumented.
3. **`plugin.json` says `0.1.0`; the repo is `0.3.2`.** `bundledSkillsVersion()`
   (`connect.ts:61`) reads that manifest, so `skillsStatus().updateAvailable`
   compares against a number nobody bumps and can never fire. The "Update
   skills" affordance is dead.

So the answer to "do we have a plugin marketplace" is yes — `.claude-plugin/`
and `.agents/plugins/` both exist — and installing from it does not give a
working board.

## Approach

- Ship with [[MCP-010]]: until discovery lands, dropping `--root` is not
  something these manifests can rely on.
- Decide the runtime question **with evidence, not assumption** ([[MCP-009]]'s
  rule): can the plugin path reach the Electron binary, or must it assume Node?
  Whichever it is, state it rather than leaving it implicit.
- Bump both `plugin.json` versions to the repo version, and add a rail check so
  they cannot drift again.

## Verification

- [ ] `claude plugin install kanmer@kanmer` from the local marketplace on a
      clean profile, then `get_status` finds this repo's board.
- [ ] `plugin:check` asserts both manifests' invocations resolve, and both
      `plugin.json` versions match the repo version.
- [ ] The runtime dependency is stated in FRD-012's install matrix, with the
      command that established it.
