## What

GUI-side follow-ups to [[CORE-117]], from its independent review (attestation `scratch/review.md` version `67020261ebcb09d2`) and its parked open questions. None is required by an FRD-032 acceptance criterion; together they are what makes captures usable rather than merely correct.

- **F-005 — standup loses the captures entirely.** `apps/gui/src/renderer/src/lib/standup.ts` drops captures from Flags and Up next without adding the "N captures awaiting a decision" line the updated `kanmer-report` prose describes, so a Backlog holding only captures shows no Up next section at all. The prose governs the agent-written standup rather than the GUI report, so no shipped contract is broken — but the GUI silently hides work that exists.
- **F-004 (GUI half) — `capture` is offered as an area default.** `Settings.tsx:943-945` enumerates resolved profiles, so `capture` now appears in the area-default selector. Choosing it freezes every profile-less ticket in that area in Backlog while none of the capture exclusions apply. The configuration is documented as unsupported (`docs/manual/profiles.md`), so the fix is to stop offering it rather than to support it. (The matching core-side error-text fix is tracked with the capture-hardening ticket.)
- **F-009 — duplicated profile lists.** `capture` was appended to two hardcoded `PROFILE_IDS` arrays (`Editor.tsx:26`, `TicketCreate.tsx:5`) rather than derived from core's effective profile set. Both arrays predate CORE-117 and it appended consistently, so this introduces no new divergence — but the next profile will have to remember three places.
- **Parked enhancements** from CORE-117's open questions: a first-class capture composer with an evidence picker (screenshot/file/link), a "hide captures" filter toggle on the board, and bulk promotion of several captures in one recorded decision.

## Why

A capture is meant to be the cheapest possible way to record an observation. Today it can be created and promoted through the MCP surface, and the GUI will show it on the board — but the standup hides it, the settings screen offers a configuration that breaks the area, and there is no composer, so the quick path is only quick for an agent.

## Approach

- Add the captures-awaiting-decision line to the GUI standup and stop suppressing the section when captures are all that remain.
- Filter `capture` out of the area-default and board-default selectors.
- Derive the renderer's profile list from core's effective profile set instead of the two hardcoded arrays.
- Composer, evidence picker, filter toggle and bulk promotion are separable — implement what fits one reviewable PR and split the rest rather than stretching the ticket.

- [ ] `capture` cannot be chosen as an area or board default in the GUI.
- [ ] The renderer's profile list comes from one source.
