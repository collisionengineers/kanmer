## What

Add a GUI-level lifecycle manager for the Cloudflare named-tunnel remote-access path, independently for each Kanmer project.

## Why

The first adapter is a locally managed named Cloudflare Tunnel exposing the bearer-authenticated loopback HTTP host. Its executable, tunnel identity, hostname, credential-file reference and lifecycle must be managed without mixing it with OpenAI Secure MCP Tunnel profiles.

## Approach

- Add per-project Cloudflare Tunnel configuration and start/stop/status controls in Settings → Connect, with explicit board-root and source-root identity.
- Persist only non-secret metadata and credential references; use OS-backed handling for the Kanmer bearer and never expose it to the adapter or diagnostics.
- Validate one exact hostname, named-tunnel credential-file mode and loopback origin; surface MCP-027 doctor results and per-project failures.
- Do not provision Cloudflare accounts, DNS, Access policies, tunnel tokens, executable downloads/updates, Quick Tunnels or a Worker-hosted MCP service.
- The independent OpenAI Secure MCP Tunnel GUI workflow is tracked by [[GUI-104]].

## Verification

- [x] A user configures, starts, stops and diagnoses a Cloudflare named tunnel without editing generated ingress.
- [x] Multiple projects retain distinct hostname/tunnel/project identities and isolated failures.
- [x] Bearers and provider credentials never enter project files, logs or UI diagnostics.
