## What

Stop Kanmer's Codex Connect flow from committing machine-specific executable, bundle, repository, and board-worktree paths into a project's `.codex/config.toml`. Establish and test a portable registration contract that works when the repository is cloned on another machine or under another user profile.

## Why

Pegasus currently tracks a generated MCP registration containing `C:\\Users\\PC\\...` paths for `Kanmer.exe`, `kanmer-mcp.cjs`, the source checkout, and `.worktrees/kanmer`. A collaborator or CI host checking out that file cannot launch Kanmer from those locations. The ticket must determine which values can rely on Codex project configuration, PATH, working-directory semantics, and Kanmer board discovery, and which installation/bootstrap change is required for a portable launcher.

## Verification

- A committed project registration contains no user-profile, installation-directory, checkout, or board-worktree absolute path.
- The same committed registration launches Kanmer and resolves the correct source repo plus canonical board worktree from two differently located checkouts or equivalent isolated test fixtures.
- Reconnect remains idempotent and preserves unrelated TOML keys.
- Failure behavior clearly explains any missing portable launcher prerequisite.
