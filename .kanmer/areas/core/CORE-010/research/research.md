# Migrating this board — research

Phase 7.1 was scheduled for "the moment a release carries the format-3
migration". It arrived earlier than that, and not by choice: core started
writing format 3 while this board still carried v2 stages, and GUI-004 was
sitting in `researching` — an id that no longer exists. A board whose tickets
are on stages the code does not know is not a board you can work.

That is the honest version of what "dogfooding" buys. The migration's first real
input was not a fixture someone designed; it was 40 tickets that had accumulated
naturally, including one in an awkward state.

Expectation going in (from the phase plan): a standard seven-stage v2 board
should collapse cleanly, with zero `needs-restage`.
