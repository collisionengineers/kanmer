## What

`npm run typecheck` at the repo root does not reach the `@kanmer/gui`
workspace. Make the root rail typecheck everything, so a green rail means what
it says.

## Why

During [[GUI-064]] I ran the documented rail, got green, and reported
"typecheck clean" on the PR. It was not: four `McpSessions` object literals in
`apps/gui/src/renderer/src/lib/update.test.ts` were missing a newly required
field. The error only surfaced later, when `release.mjs` ran
`npm run typecheck -w @kanmer/gui` directly — **after** the PR had been merged.
Fixed in `c8b94a4`.

Two gaps lined up:

- the root `typecheck` script does not include the GUI workspace, and
- **vitest does not typecheck**, so a full green test run says nothing about
  types in test files.

Test files are exactly where this bites: they construct shared types by hand, so
they break first when a type gains a field, and they are the least likely place
anyone re-checks.

AGENTS.md §10 is the verification checklist people follow before calling
something done. If the commands it names do not cover the repo, the checklist
launders a false claim — which is what happened here.

## Approach

- Add the GUI workspace to the root `typecheck`, and check whether any other
  workspace is missing while there.
- Confirm the root script covers **test files**, not just `src` — that is the
  half that failed.
- Update AGENTS.md §10 if the command changes.

## Verification

- [ ] Reintroduce the exact `c8b94a4` error (drop `pids` from a literal in
      `update.test.ts`) and confirm the **root** `npm run typecheck` fails.
- [ ] `npm run typecheck` clean on current main.
- [ ] Every workspace appears in the run's output — no silent omissions.
