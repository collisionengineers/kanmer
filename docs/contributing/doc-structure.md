# Document structure

**Generated mirror — never authoritative.** The board's `board.yml` (`docs:` block, or the shipped
defaults when it is absent) is the source of truth; this file exists so a human can read the
current document model without opening YAML. Regenerated by `kanmer-docs` whenever the model
changes (FRD-014 R4).

Reflects the board at `.worktrees/kanmer` on `kanmer-board`, storage format 2.

## Two different things called "docs"

Keep these apart — conflating them is a known failure mode (FRD-004 R5):

- **Governing documents** live in this repo's `/docs/` tree (PRD / FRD / ADR). A ticket points at
  them through its frontmatter `refs`, and that is what the leave-Backlog gate checks.
- **Ticket documents** live inside the ticket's own folder under `.kanmer/areas/<area>/<ID>/`.
  They are the pipeline: research, plan, proof and so on.

## Ticket document types

| Type | File | Requires first | Notes |
|---|---|---|---|
| `research` | `research.md` | — | findings |
| `impact` | `impact.md` | — | where the change lands (becomes `files/` in v3) |
| `open-questions` | `open-questions.md` | — | questions only the user can answer |
| `plan` | `plan.md` | `research`, `impact` | |
| `checklist` | `checklist.md` | `plan` | carries progress (`- [ ]` / `- [x]`) |
| `post-implementation-report` | `post-implementation-report.md` | — | the reviewers' brief |
| `proof` | `proof.md` | — | evidence gathered on merged `main` |

Plus `scratch-<slug>.md` running notes, which are exempt from typing and from every gate.

## Stage gates

Seven stages: **backlog → researching → planning → implementing → review → verifying → done**.

| Boundary | Requires |
|---|---|
| leaving `backlog` | a governing doc — a `refs` entry classified as prd/frd/adr, **or** `docs_todo: true` |
| leaving `researching` | `research`, `impact` |
| leaving `planning` | `plan`, `checklist` |
| entering `review` | `post-implementation-report` |
| entering `done` | `proof` |

A gate is checked against **every** boundary a move crosses, so a multi-stage jump cannot skip
one; it is blocked by the first unmet boundary. Creation is ungated — a ticket may be created
directly in any stage, which is what makes backfilling finished work possible.

Call `get_doc_gates(id)` before any move rather than reasoning about this table: it reports what
is required, what is satisfied, and what the next move needs.

## Governing-doc path globs

| Kind | Glob |
|---|---|
| `prd` | `docs/product/prd/**` |
| `frd` | `docs/functional/frd/**` |
| `adr` | `docs/architecture/adr/**` |

These follow the docs-template tree landed in Phase 0.1. A `refs` path that matches none of them
is stored but classifies as no kind, so it does not satisfy the leave-Backlog gate.

## Known limitation

On a project whose board lives in a Git worktree (`.worktrees/kanmer`, the shipped model per
FRD-020), **`refs` cannot currently be set at all**: core validates each path against the store's
root, which is the board worktree, while the governing documents live in the source checkout.
`create_item`/`update_item` reject any `refs` entry with *"does not exist under the project root"*.
Use `docs_todo: true` until this is fixed, and record the intended governing documents in the
ticket body.

## v3 changes ahead

Format 3 reshapes most of this: six fixed stages, documents become **folders** (containment
defines type, unlimited docs per type), `impact` becomes `files`, `reference/` arrives for
human-supplied inputs, and gates come from a per-ticket **profile** rather than one board-wide
set. See FRD-002, FRD-003 and FRD-007.
