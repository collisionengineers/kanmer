## What

Run the two-version update cycle that [[GUI-064]] could not: **0.3.2 → the next
release**, driven by the app rather than by hand. Close the two boxes GUI-064
left open rather than ticking them to look finished.

## Why

GUI-064 shipped in 0.3.2 and was verified by performing the update manually —
stopping the MCP server, confirming the install folder went from `blocked: 2` to
`blocked: 0`, then installing. That proves the diagnosis and the mechanism. It
does **not** prove the shipped code does it by itself, because the fix runs in
the version *doing* the updating and the machine was on 0.3.0 at the time.

Two specific things remain unproven:

1. **The refusal dialog has never been seen by a human.** Its logic is
   unit-tested and both message strings are verified present in the installed
   asar, but nobody has looked at it on screen. That is half the user-facing
   value of GUI-064.
2. **Respawn timing was never measured** (GUI-064 checklist box 1). The
   instrumentation line in the run script had a PowerShell syntax error and
   printed nothing. What is known is only that no replacement server appeared
   that one time. `STOP_ROUNDS = 3` and `SETTLE_MS = 700` were therefore chosen
   without the number they were supposed to be sized from.

Both are answerable for free the next time a release goes out, which is why this
is a ticket rather than a note nobody reads.

## Approach

- With 0.3.2 installed and a **live agent MCP session**, take the update through
  the app's own banner. Expect it to complete unaided.
- Capture the lock probe immediately before the installer runs — expect
  `blocked: 0` where GUI-064 measured `blocked: 2`.
- **Force the refusal.** Start an `ELECTRON_RUN_AS_NODE` holder our predicate
  cannot stop, take the update, and screenshot what the user sees. It must name
  the projects and must not be `uninstallFailed: 2`.
- **Measure respawn properly** this time: kill a live MCP server, poll for a
  replacement under `$INSTDIR`, record whether and how fast one appears. Feed
  the number back into `STOP_ROUNDS` / `SETTLE_MS` if it contradicts them.

## Verification

- [ ] An update with a live agent session installs with no manual step.
- [ ] Screenshot of the refusal dialog, naming a project — `proof:visual`.
- [ ] Respawn timing recorded as a number, and the retry constants either
      confirmed or corrected against it.
- [ ] GUI-064's proof.md "What this run does NOT prove" section is answered
      point by point.
