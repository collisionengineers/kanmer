## Ripple effects

- A stable GitHub check appears on every pushed `v*` tag; operations documentation and any future ruleset must use its exact displayed name.
- CI packaging consumes substantial Windows runner time. Use one job, a repository/tag-scoped concurrency key, and an explicit timeout; do not add a platform matrix.
- The workflow's local artifacts must be produced from the tagged commit before remote digest comparison, otherwise the integrity check is meaningless.
- Published-asset validation may initially see no release or partial assets while the laptop publisher is still running. Bounded polling is part of correctness, not a flaky-test workaround.
- The first successful production tag and one controlled negative run become proof; no source-only test can establish GitHub trigger and release-API behavior.

## Out of scope

- Publishing, creating, editing, repairing, promoting, demoting or deleting GitHub releases.
- Changing `scripts/release.mjs` ownership or implementing GUI-092/GUI-093.
- Adding Linux/macOS jobs, code signing, release candidates, merge queues or automatic rollback.
- Changing updater behavior, release asset naming, installer targets or the verification pyramid.
- Requiring this tag job as a pull-request check; `verify` is the PR check.
