## What

`get_status` reports which server build is answering — its version and the file
it was loaded from — so two hosts disagreeing about the gates becomes visible
instead of silent.

## Why

Measured on this machine, 2026-08-16, on **one board**:

```
.codex/config.toml → AppData\...\Kanmer\resources\mcp\kanmer-mcp.cjs   sha e92a2679…
.mcp.json (Claude) → <repo>\plugins\kanmer\mcp\kanmer-mcp.cjs          sha 96fe9f8a…

grep -c questions-resolved     installed: 0        repo: 1
```

The installed app was built at 16:14; [[SKILL-012]] merged at 17:35. **Codex was
enforcing a different gate set than Claude, on the same tickets, and nothing
anywhere said so.** Both hosts reported a healthy connection.

That is the failure mode: not that the builds differ — they will, between a
released app and a working checkout — but that the difference is undetectable
from inside a session. An agent cannot tell whether the gate it just passed is
the gate the board actually declares.

## Not a duplicate of CORE-023

[[CORE-023]] asks whether a **repo's** Kanmer is older than the agent's, and
what is stale about it. This asks which **binary** is answering right now. A
repo can be perfectly current while the host talks to a six-week-old server.
They should cross-reference, not merge.

## Approach

- Add version + bundle identity to `get_status`: the package version, the
  resolved script path, and a build stamp that distinguishes a packaged bundle
  from a checkout build.
- Include how the board root was resolved (from [[MCP-010]]) — the two questions
  an agent has at session start are "which board" and "which server", and they
  belong in the same answer.
- Keep it cheap: this runs on every session's first call.

## Verification

- [ ] Reproduce the drift above (both sha256s and both `questions-resolved`
      counts) as the falsifying case.
- [ ] `get_status` from each host names its own build distinctly, on that same
      pair.
- [ ] The stamp survives packaging — a packaged app reports the packaged bundle,
      not a dev path.
