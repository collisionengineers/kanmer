## What

`docs/functional/frd/FRD-024-in-app-manual.md` R4 has two clauses. One mandates a
"?" affordance on Settings tabs that deep-links to the relevant manual chapter —
that clause is being removed by [[GUI-074]], deliberately.

The other clause mandates a "?" on **gate-block messages**, opening the
"Tickets, profiles & gates" chapter. **That one was never implemented at all.**
Repo-wide search during GUI-074's research found no match for the chapter title
and no match for any gate-block help affordance. AC3 covers it and has never been
true.

Decide and act: either build it, or withdraw it from the FRD.

## Why

This was found while researching [[GUI-074]] and deliberately kept out of it.
GUI-074 is a removal ticket; folding an unimplemented-feature finding into a
removal hides it, and the release scope for 0.3.3 was fixed before this surfaced.

The requirement matters more than the usual stale-doc case: a gate refusal is
exactly the moment a user does not know what a profile is or why a document is
owed. If contextual help belongs anywhere in Kanmer, it belongs there. So this
is a real product question — "is the gate-block the one place help should be
offered?" — not just doc hygiene.

Note the surrounding context, because it cuts both ways: GUI-074 removes the
*other* contextual-help entry point, so if this clause is also withdrawn, Kanmer
has no contextual help at all and the manual is reachable only via F1 and the
Help menu. That may be the right answer — [[DOC-007]] is rewriting the manual
into something worth reading, which is a precondition for pointing anyone at it —
but it should be chosen, not arrived at.

## Approach

- Read FRD-024 R4 and AC3 as they stand after GUI-074's amendment.
- Decide with the operator: implement the gate-block affordance, or withdraw the
  clause and AC3.
- If withdrawing, say in the FRD that it was never built and was withdrawn — not
  that it was removed, which would imply it once worked.
- If implementing, the gate refusal already names the unmet requirement and
  boundary; the affordance should carry that context into the chapter rather than
  opening it cold.

## Verification

- [ ] FRD-024 R4 and AC3 describe only what is actually true of the shipped app.
- [ ] If implemented: the affordance appears on a real gate refusal and opens the
      right chapter, with proof.
- [ ] If withdrawn: the FRD records that it was never built, and the decision to
      leave Kanmer without contextual help is stated rather than implied.
