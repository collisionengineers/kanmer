## What

Investigate, specify and build a provider-neutral secure tunnel system that can expose a private Kanmer MCP server to remote AI hosts without coupling Kanmer's core tunnel model to OpenAI, Cloudflare or any single vendor.

## Why

The validated OpenAI Secure MCP Tunnel proves the use case, but its control plane, identity, workspace associations and bundled Cloudflare transport are vendor-specific. Kanmer needs a general architecture before the GUI grows around one provider's profile format and lifecycle.

## Approach

- Survey remote-MCP capabilities and constraints across relevant AI hosts and tunnel/relay technologies, separating MCP transport, tunnel transport, identity, authorization and provider registration.
- Define a stable Kanmer tunnel-provider contract with capability discovery and adapters for vendor-managed tunnels, self-hosted relays and standards-compatible HTTP MCP endpoints.
- Preserve local stdio as the canonical server surface while supporting secure remote reachability, per-project isolation, concurrent projects, health/status, lifecycle control and auditable operations.
- Design secret storage/reference, least-privilege authorization, TLS/mTLS/OAuth options, revocation, rotation, logging/redaction and explicit exposure boundaries.
- Implement the minimum reusable core plus one validated non-OpenAI path; keep OpenAI support as an adapter rather than the contract.
- Produce governing FRD/ADR documents before implementation so [[GUI-095]] can consume the general model rather than hard-code OpenAI behavior.

## Verification

- [ ] A provider/transport capability matrix and threat model identify what is genuinely portable versus adapter-specific.
- [ ] The same Kanmer project can be exposed through at least two independently implemented provider/relay paths without changing the MCP tool server.
- [ ] Multiple projects run concurrently with unambiguous routing, isolated credentials and no cross-project tool access.
- [ ] Failure, reconnect, revoke, rotate, update and cleanup behaviors are exercised without exposing secrets or opening unintended ingress.
- [ ] [[GUI-095]] can manage the resulting abstraction without provider-specific logic leaking into shared GUI state.
