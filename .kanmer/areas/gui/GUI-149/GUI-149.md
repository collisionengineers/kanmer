## Why
Observed 2026-09-03 while diagnosing why Kanmer MCP keeps breaking in Claude Code after Connect.

1. `installedElectronInvocation()` (`apps/gui/src/main/connect.ts`) still registers Claude Code (`claude mcp add kanmer -s project` → `.mcp.json`) and OpenCode (`opencode.json`) with `command: <absolute Kanmer.exe>`, `args: [<absolute resources/mcp/kanmer-mcp.cjs>, "--root", <absolute board root>, "--repo-root", <absolute repo root>]` and `ELECTRON_RUN_AS_NODE=1`. Codex already uses the portable installer-owned launcher (`powershell.exe … & (Join-Path $env:LOCALAPPDATA 'Kanmer/bin/kanmer-mcp.cmd')`, FRD-012 R1e) with no machine paths at all. The absolute form bypasses the versioned runtime under `%LOCALAPPDATA%/Kanmer/mcp/current` that the shim prefers, and goes stale on a manual reinstall (AGENTS.md §8: "registered MCP command path can go stale … not detected today").
2. Connect never adds what it writes to the target project's `.gitignore`. `.mcp.json`, `.codex/config.toml`, `opencode.json` and `.opencode/skills/` are ignored in the Kanmer repo only because this repo's committed `.gitignore` lists them; in any other user project they are committed, with that user's absolute paths in them. FRD-012 R1c requires registration files to stay gitignored.

Board discovery makes the absolute paths unnecessary: from cwd = project dir the server finds `<project>/.worktrees/kanmer` (`cwd-worktree`) and derives the repo root (`repoRootSource: "derived"`); the staleness detector already treats a registration without `--root` as valid. Claude Code spawns project `.mcp.json` servers with cwd = project dir, and Connect spawns `claude.exe` via `execFile` without a shell, so the `&` in the PowerShell argument passes through verbatim.

## Outcome
- `serverInvocation()` returns the one portable launcher contract for codex, claude **and** opencode; `installedElectronInvocation()` is removed; the launcher `--probe` gates all three before any file is written (no absolute-path fallback, as Codex today).
- `.mcp.json` and `opencode.json` carry no `Kanmer.exe`, script path, `--root`, `--repo-root` or `ELECTRON_RUN_AS_NODE`; only `KANMER_BOARD_BRANCH` remains in env. The branch-change reconcile path (`mcpServersMerge`/`opencodeMerge`) emits the same shape.
- The core staleness detector reports a legacy absolute descriptor in `.mcp.json`/`opencode.json` as `behind` (fix: reconnect), generalising `isCurrentCodexRegistration()`.
- After a successful registration, Connect appends the provider-derived paths (`register.configPath`, `install.skillsDir/`) to `<project>/.gitignore` via the existing idempotent `ensureIgnore()` helper, only when the project has a `.git`; best-effort, noted in the result, never a Connect failure. Disconnect leaves the lines.
- FRD-012 R1/R1c/R1e/R7, AGENTS.md §8 gotcha and `.gitignore` comment, `docs/manual/connect.md` updated.

## Verification
- Unit: providers/connect/staleness tests assert the three registrations contain none of `Users`, `Kanmer.exe`, `--root`, `--repo-root`, `cwd`, `ELECTRON_RUN_AS_NODE`; probe failure blocks all three; gitignore appended once, not twice, and not without `.git`.
- Real host (packaged build): in a scratch git repo with a board, Connect all three; `git status` shows only `.gitignore`; `claude mcp list` Connected and `claude -p` calling `get_status` returns `rootSource: cwd-worktree`; `codex` and `opencode` call `get_status`; `get_status.repo.stale` has no `mcp-registration` row, and a hand-edited legacy `.mcp.json` yields one.
