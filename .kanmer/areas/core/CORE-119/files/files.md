## Ripple effects

- **Rail duration.** `VERIFY_STEPS` gains a step, so every PR, every push to `main`, every `v*` tag and `npm run release --ticket` all get longer. Bounded by the runner's fail-closed `KANMER_GOLDEN_BUDGET_MS`; an overrun is a deterministic failure, not a slow green.
- **`npm test` gains `scripts/golden-promotion.test.mjs`** automatically through `test-scripts.mjs`. No config, no `package-lock.json` change.
- **No generated artefact changes.** Nothing under `packages/core/src` or `packages/mcp-server/src/index.ts` is touched, so the committed `plugins/kanmer/mcp/kanmer-mcp.cjs` bytes, the MCPB, the 41-tool count and `check-plugin-sync.mjs`/`check-mcpb-sync.mjs` results are unchanged. New `.mjs` files under `packages/mcp-server/src/` are invisible to `tsc` (as `smoke.mjs` already is) and to the esbuild standalone bundle.
- **`npm run typecheck` is unaffected** — `.mjs` files in these locations are not part of any `tsconfig` include.
- **New temp-dir prefix `kanmer-golden-`** joins the twelve already in use; no collision.
- **CORE-137 changes shape.** Its promotion acceptance becomes `npm run golden:promotion …` plus the recorded transcript, instead of retyped tool calls through an out-of-repo client. CORE-137's body already names the deltas; this ticket does not edit CORE-137.
- **Docs.** Only `AGENTS.md` §6/§10. No `/docs/` file changes, so `npm run verify:docs`, `check-doc-numbering.mjs` and `check-doc-structure.mjs` are unaffected and no doc-numbering slot is consumed.

## Out of scope

- **Refactoring `smoke.mjs`, `smoke-protocol.mjs` or any existing smoke** into shared modules. 4132 lines with no exports; a mechanical extraction during a release window is a large diff with no acceptance value. The four idioms are copied instead. Named follow-up if ever wanted, not filed here (it fails the HZN-008 scope test — no named FRD acceptance criterion requires it).
- **Changing any production source.** No new tool, no new stage, no new field, no change to `errors.ts`, `store.ts`, `reconciliation.ts`, `release.ts`, `merge-gate.ts` or `index.ts`. If a scenario cannot be expressed against the shipped surface, it is recorded `unavailable` — FRD-035 edge case 1 — and reported, not worked around by widening the product.
- **A metrics platform.** FRD-035 says the evaluation "records" outcomes, corrections, churn, plan deviations, review cycles, stuck stages, recovered leases, incorrect-project attempts, duplicate work and observable tool/token cost. This ticket records them as counters in the transcript JSON. It builds no dashboard, no time series, no aggregation across runs, and no scoring model — MASTERPLAN's "workflow metrics" non-goal stands.
- **A generic provider framework.** HZN-008 Non-goals forbids it. The simulated tier is one injected `ReconciliationRun`, not an adapter abstraction.
- **Live GitHub, live CI or live network of any kind** in `npm run golden`. Provider-derived findings are `simulated` from injected evidence or `unavailable`.
- **Anti-churn tests E and G.** Agent-judgement properties with no server-observable contract; pinned as skill prose by SKILL-039's `verify-skill-prose.mjs` entries. Parked in `open-questions` with that reason.
- **Editing `MASTERPLAN.md`** to retire its "no golden-board eval harness" non-goal. MASTERPLAN is the superseded v0.3 plan; PRD-002 requirement 8 governs. Recorded as a residual doc inconsistency in `open-questions` → Parked.
- **Editing FRD-035, ADR-0021 or FRD-034.** This plan Meets them. The FRD-034 Amendment text belongs to SKILL-039.
- **Automating the live cut-over.** `golden:promotion` rehearses against a *copied* board and reports; installing, stopping the stable server and marking a candidate stable stay operator actions in CORE-137, per ADR-0021.
- **The GUI.** No `apps/gui` change; the packaged-boot smoke stays the existing `KANMER_SMOKE` invocation the promotion contract merely records.
