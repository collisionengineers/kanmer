## What

Keep the agent MCP runtime outside the installer directory (or provide an equivalent update-safe runtime boundary) so an installed-app update does not kill or invalidate live MCP sessions.

## Why

The archived MCP-005 audit found a unique residual defect: GUI-064 fixes the NSIS installer failure by stopping live MCP sessions before update, but the registered MCP command still runs from `process.execPath` under `$INSTDIR`, and the bundle lives under `$INSTDIR/resources`. Updates therefore still terminate live agent sessions. GUI-099 through GUI-102 cover portable registration/shim lifecycle but do not yet prove runtime survival outside `$INSTDIR`.

## Approach

Research and plan the smallest update-safe runtime/launcher boundary that preserves provider registrations, cwd/root discovery, packaged MCP identity, uninstall cleanup, and existing stop/warning behavior. Reuse GUI-099–GUI-102 launcher work where fit; do not weaken installer safety or silently orphan existing registrations.

## Verification

Prove a real packaged update with an active MCP session: the session remains usable or reconnects through the stable runtime boundary, registration remains valid, updater/uninstall cleanup is correct, and no stale runtime or secret remains.

## Non-goals

No new remote transport, tunnel, bearer behavior, or unrelated updater redesign.
