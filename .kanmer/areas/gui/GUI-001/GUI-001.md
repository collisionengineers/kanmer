FRD-020 R5. `setKanmerGitPreferences` (`apps/gui/src/main/settings.ts:87-93`) only persists the branch string. Nothing migrates existing projects: the next `openProject` calls `ensureBoardWorktree` with the new name and creates or adopts a worktree for it, leaving the old branch behind and its commits unreachable from the new one.

The FRD previously claimed this worked ("push new before deleting old"); corrected in Phase 0.2 to R5, marked not built.

Related: `removeBoardWorktree` (`apps/gui/src/main/kanmerGit.ts:108-110`) is dead code, never called from anywhere — likely the intended other half of this.

End state per FRD-020 R5: push the new branch before deleting the old; worktree path unchanged so MCP registrations stay valid.
