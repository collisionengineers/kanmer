# Research — CORE-115: renewable workspace leases

## Question

How do the CORE-121 bootstrap claim (`taken_at`, `claim_expires_at`, `claim_controller`, transfer/renew) and the CORE-114 revision CAS become the FRD-030 lease: a full lease record with identifiers, heartbeat/expiry configuration, atomic revision-safe acquisition and renewal (`LEASE_EXPIRED` / `REVISION_CONFLICT`), one live writer per workspace, evidence-backed reclaim that preserves dirty work, and one migration path for legacy claims — while the live board stays readable by the installed v0.3.12 server and the tool roster stays at 38? And is batch mode separable?

## Findings

- **Claim state today is four legacy fields plus four CORE-121 fields on ticket frontmatter.** `ItemFrontmatterSchema` (`packages/core/src/types.ts:431-447`) carries `taken_at`, `branch`, `worktree`, `claim_expires_at`, `claim_controller`, `review_round`, `remediation_budget`. `claimState()` (`types.ts:627-639`) classifies `unclaimed | live | expired`, deriving expiry for a legacy claim from `taken_at + claimExpiryMinutes` — this is already the FRD-030 "one migration path" and must stay the single rule. `board.yml` has `claimExpiryMinutes` (default 30, `types.ts:383`, `DEFAULT_CLAIM_EXPIRY_MINUTES` at `:620`). No heartbeat cadence, lease id, workspace id, run ids, provider or phase exist.
- **Unknown frontmatter keys survive v0.3.12.** `ItemFrontmatterSchema` is `.passthrough()` (`types.ts:468`) and `serialiseItem` emits `KEY_ORDER` keys then any extras (`packages/core/src/frontmatter.ts:5-33, 49-58`). New optional `lease_*` fields are therefore readable and preserved by the installed server and GUI; no format bump (`CURRENT_FORMAT = 3`, `version.ts:14`) and no `migrate_board` step are needed. Same conclusion CORE-121 reached and proved with its "v0.3.12 ticket without claim fields" test (`claims.test.ts:183`).
- **The store's claim verbs are not serialised across processes (CORE-114 F-009).** `takeTicket` (`store.ts:1087-1143`), `releaseTicket` (`:1145`), `transferTicket` (`:1171-1222`) and `renewTicket` (`:1224-1247`) each do read → `assertRevision` → `writeFileAtomic`; two processes can both pass the CAS from the same revision and the later rename wins. The board already has a cross-process lock primitive: `withExclusiveFileLock(lockFile, work)` (`io.ts:452`, stale-owner recovery, bounded retries) used by `setBoard`/`updateBoard` (`store.ts:368, 380`). `.kanmer/**/*.lock` and its owner/stale markers are gitignored on the board branch (`.worktrees/kanmer/.gitignore:3-5`), so a lease lock file under `.kanmer/` is safe to create.
- **`renew` checks ownership by name only.** `renewTicket` accepts when `assignee === actor || claim_controller === actor` — MCP client names are not durable identities (`execution-packet.ts:494`). FRD-030 AC2 requires renewal to name the current lease id and revision. The document-inclusive `revision` (`store.getRevision`, `rev1:` over ticket file + pipeline docs, scratch excluded, `store.ts:304-321`) changes when a worker writes plan/report docs, so it is a usable but noisy renewal token; a lease-local counter is the precise one.
- **One writer per workspace is enforced only at packet time, not at take time.** `get_execution_packet` refuses duplicate ticket worktrees, board/source checkouts, aliases and foreign repositories (`execution-packet.ts:254-362`, FRD-016 compiled end state), but `takeTicket` only refuses the board worktree (`assertNotBoardWorktree`, `worktree-guard.ts:33`). Two tickets can be *taken* on the same branch/worktree (smoke does exactly that at `smoke.mjs:2145, 2328` to set up packet refusals). `listItems` (`store.ts:532`) is available inside the store for an occupancy scan.
- **Reclaim evidence already exists at the MCP boundary.** `collectReconciliationEvidence` / `workspaceEvidence` (`packages/mcp-server/src/reconciliation.ts:213-310`) inspects the recorded worktree (`not-recorded | clean | dirty | missing | unavailable`, board-worktree flag, `claimIdentity` via `--git-common-dir` and `symbolic-ref`), PR state via `gh`, commits reachability and proof. Core's `reconcileEvidence` (`packages/core/src/reconciliation.ts`) already names the FRD-030 recovery cases: `DIRTY_WORKSPACE_PRESERVED`, `WORKSPACE_MISSING`, `CLAIM_WITHOUT_RECORDED_WORKSPACE`, `BOARD_WORKTREE_PROTECTED`. Core cannot run git; the MCP `take_ticket` handler (`index.ts:1405-1453`) can collect evidence before calling the store.
- **`transfer` is the reclaim verb.** CORE-121 defined `transfer` as the only non-`force` recovery of an expired claim (refuses `CLAIM_LIVE`, keeps branch/worktree/`taken_at`, records old → new controller in activity and `scratch/execution.md` `## Transitions`). The skills already depend on it (`kanmer-auto/SKILL.md:62-66`, `kanmer-execute/SKILL.md:136-141`, `kanmer-closeout`). Extending `transfer` with evidence, rather than adding a `reclaim` action, keeps the enum and the roster stable (38 tools, `smoke.mjs:62`).
- **The GUI releases through the store.** `ipcMain.handle(CH.releaseTicket)` → `store.releaseTicket` (`apps/gui/src/main/index.ts:1178-1180`); cards show only `taken_at` (`Board.tsx:368`, `Editor.tsx:973`). Clearing lease fields inside `releaseTicket` covers the GUI without touching `apps/gui`.
- **Activity is best-effort and gitignored; `scratch/execution.md` is the committed audit.** `ActivityEntry.op` is a closed union (`activity.ts:14`); transfer already appends a committed transition line (`store.ts:973-978`). Lease events (acquire, renew with phase change, reclaim with evidence summary) can use the same two channels.
- **Packet and inspector surfaces expose the claim.** `ExecutionPacketClaim` (`execution-packet.ts:66-72`) and `ReconciliationEvidence.claim` (`types.ts:667-678`) carry state/expiry/controller/round/budget; a worker needs the lease id, lease revision, heartbeat cadence and phase from the packet to renew correctly.
- **Batch mode is separable.** FRD-030 AC4/AC5 need a batch record, frozen membership, shared PR/attestation with per-member proof and cleanup-waits-for-all. The lease contract's only batch dependency is the `WORKSPACE_OCCUPIED` rule ("a ticket cannot occupy two active workspaces; one live writer per workspace"), and batch mode is precisely the deliberate exception to it. Nothing in AC1–AC3 needs batch fields. Decision recorded in `open-questions`: batch mode split into its own ticket, blocked by this one.
- Governing constraints: FRD-030 (all), FRD-034 (controller acquires leases, reconciles after every worker result), HZN-008 context (one active writer per workspace, revision/lease CAS on every mutation, no silent deletion of dirty work, live board stays on v0.3.12 — additive fields only). No project-declared research source applies (`get_sources` → `declaredCount: 0`).
- Test rails: `packages/core/src/claims.test.ts` (CORE-121 contract, `ageClaim` helper), `store.test.ts:685` (take/release/force), `packages/mcp-server/src/smoke.mjs:2180-2230` (claim contract over MCP), `reconciliation.test.mjs` (evidence collector with an injected `run`). AGENTS.md §10 verification checklist; `npm run verify` is the authoritative rail and `plugin:check` must run from the main checkout.

## Implications

- **Lease = the existing claim fields plus additive `lease_*` fields**, all optional. Absent `lease_id` on a taken ticket means a *legacy lease*: `leaseState()` (successor of `claimState`, same expiry rule) classifies it and the first lease mutation (renew/transfer) writes the full record. This is the single migration path; `claimState` stays as a thin alias so CORE-121/122 callers keep working.
- **Lease record fields:** `lease_id` (uuid), `lease_revision` (int, +1 on every lease write), `lease_controller_run`, `lease_worker_run`, `lease_workspace` (normalised worktree, else branch), `lease_provider`, `lease_phase` (`implementing | running-command | review | verifying | closeout`), `lease_heartbeat_at`, `lease_reclaimed_from` (previous controller, written on transfer). `taken_at` remains claimed-at, `claim_expires_at` remains expiry, `claim_controller` remains controller identity.
- **Configuration:** `board.yml` `claimExpiryMinutes` (30) stays; add `leaseHeartbeatMinutes` (default 5) and `leaseCommandMaxMinutes` (default 120, the bound for an explicit `running-command` extension). Reported in the packet's `claim` block and `get_status` so cadence is explicit and testable.
- **Atomicity (F-009):** every lease mutation runs under `withExclusiveFileLock(.kanmer/leases.lock)` — one board-wide lease lock, because acquisition must also scan sibling tickets for workspace occupancy. Inside the lock: re-read, `assertRevision`, lease checks, write.
- **Acquire (`take`):** refuses `LEASE_LIVE` when another controller's lease is live; refuses `WORKSPACE_OCCUPIED` when any other non-archived ticket holds a live *or expired-but-unreleased* lease on the same normalised worktree or branch (a final claim remains until closeout, so the workspace stays owned); a same-controller re-take of its own ticket is refused as today unless `force` (unchanged semantics; `force` never bypasses the workspace rule).
- **Renew:** requires `lease_id` + `lease_revision` when the ticket has a lease (`LEASE_EXPIRED` when the id is no longer current, `REVISION_CONFLICT` when the revision is stale — a `Conflict:` message so the MCP layer classifies it); a legacy lease renews by owner check and is migrated. Renewing one's own past-expiry lease that nobody reclaimed is allowed (expiry is not deletion). Optional `phase`, and for `running-command` an `extend_minutes` bounded by `leaseCommandMaxMinutes`.
- **Reclaim (`transfer`):** the MCP handler collects `ReconciliationEvidence` first and passes a `recovery` summary (workspace state, claim identity, PR state, commit count) into `store.transferTicket`; refuses on `boardWorktree` or `foreign-repository`; otherwise records the summary and old → new controller in `## Transitions` and `lease_reclaimed_from`, never deleting or resetting anything. Dirty / committed-no-PR / missing-worktree all transfer with their evidence recorded so the new controller resumes or recreates from the branch.
- **Surfaces:** `take_ticket` gains optional `lease_id`, `lease_revision`, `phase`, `extend_minutes`, `controller_run`, `worker_run`, `provider` params (no new action, no new tool); packet `claim` and reconcile `claim` blocks gain the lease fields and cadence; `get_execution_packet` occupancy refusal unchanged.
- **Docs:** plugin `tool-reference.md`, AGENTS.md §4 field list and a §8 gotcha, `docs/manual` claim mention, FRD-030 stays draft (owner document).
