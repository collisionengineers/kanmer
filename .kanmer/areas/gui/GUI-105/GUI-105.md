## Problem

Format-3 documents are folders. The MCP surface can expose exact readable document paths, but the GUI only opens a document type's conventional index file. A research file such as `research/portable-connect-integration.md` can therefore exist and satisfy a gate while appearing absent in the GUI.

## Desired outcome

The GUI presents the same ticket-document inventory that a current MCP client can inspect. A user can discover, select, read, and edit every Markdown document path beneath a ticket's document folders, including nested and custom-named files, without needing filesystem knowledge.

Keep the existing document-type workflow and clearly distinguish gated documents from scratch, references, and assets. Use the shared core inventory; do not create a separate renderer-side filesystem scan.

Related MCP capability: [[MCP-029]]. Editor context: [[GUI-096]].

## Verification

- A ticket containing only `research/portable-connect-integration.md` visibly shows and opens that file in the GUI.
- Nested paths are selectable and edits preserve the exact path.
- The GUI inventory agrees with the MCP `documentPaths` inventory for the same ticket.
- A bare document-type tab remains compatible with its conventional index document.
- Existing checklist progress, scratch notes, references, and asset handling remain intact.
