## What

`get_status` reports which server build is answering — its version and the file
it was loaded from — so two hosts disagreeing about the gates becomes visible
instead of silent.

## Why

Measured on this machine, 2026-08-16, on **one board**:

```
.codex/config.toml → AppData\...\Kanmer\resources\mcp\kanmer-mcp.cjs   sha e92a2679…
.mcp.json (Claude) → <repo>\plugins\kanmer\mcp\kanmer-mcp.cjs          sha 96fe9f8a…

grep -c questions-resolved     installed: 0        repo: 1
```

The installed app was built at 16:14; [[SKILL-012]] merged at 17:35. **Codex was
enforcing a different gate set than Claude, on the same tickets, and nothing
anywhere said so.** Both hosts reported a healthy connection.

That is the failure mode: not that the builds differ — they will, between a
released app and a working checkout — but that the difference is undetectable
from inside a session. An agent cannot tell whether the gate it just passed is
the gate the board actually declares.

## Not a duplicate of CORE-023

[[CORE-023]] asks whether a **repo's** Kanmer is older than the agent's, and
what is stale about it. This asks which **binary** is answering right now. A
repo can be perfectly current while the host talks to a six-week-old server.
They should cross-reference, not merge.

## Approach

- Add version + bundle identity to `get_status`: the package version, the
  resolved script path, and a build stamp that distinguishes a packaged bundle
  from a checkout build.
- Include how the board root was resolved (from [[MCP-010]]) — the two questions
  an agent has at session start are "which board" and "which server", and they
  belong in the same answer.
- Keep it cheap: this runs on every session's first call.

## Verification

- [x] Reproduce the drift above (both sha256s and both `questions-resolved`
      counts) as the falsifying case.
- [x] `get_status` from each host names its own build distinctly, on that same
      pair.
- [x] The stamp survives packaging — a packaged app reports the packaged bundle,
      not a dev path.

## Outcome

**Shipped** in PR [#46](https://github.com/collisionengineers/kanmer/pull/46),
merged 2026-08-16 as `efdc9f3`. Proof gathered on merged `main` in a clean
detached checkout with fresh `node_modules` — see `proof`.

`get_status` now opens with an identity block: `projectRoot`, **`repoRoot`**,
`rootSource`, **`repoRootSource`**, and a **`server`** block (version, resolved
path, runtime sha256 + short prefix, mtime, size, build shape). The falsifying
pair that previously returned byte-identical JSON is now distinguishable in both
directions — the old installed build **omits** the block, and that absence is
the documented signal "pre-0.3.3".

Shipped differently than first sketched, all recorded in `open-questions` under
"Decided during planning":

- **`repoRootSource` was added** (`flag`/`env`/`derived`) beside `repoRoot`. The
  measured second divergence *is* that codex passes `--repo-root` and
  `.mcp.json` does not, so naming how the repo root was reached is the same fact
  `rootSource` gives for the board root.
- **`repoRoot` sits top-level**, beside `projectRoot`/`rootSource`, rather than
  inside `server{}` — it is a root, not a property of the binary, and
  `rootSource` is fixed top-level by [[MCP-010]].
- **No module-`format` field**: `get_status.format` already means the *store*
  format. Module format is implied by `build`.
- The `RootSource` type is **imported** from `@kanmer/core`, not re-declared, so
  the seven-value vocabulary — including MCP-010's late-added `init` — cannot
  drift. `smoke:discovery` exercises `rootSource=init` end-to-end.

**Release rail changed, operator-authorised.** `scripts/release.mjs` gains step
5b: rebuild the MCP bundle after the version bump and before the pack, so the
release commit carries it. Demonstrated rather than argued — bumping 0.3.2→0.3.3
changes the bundle's bytes and fails `plugin:check` until it is rebuilt. The two
rules this widens were **rewritten in prose, not deleted**. [[GUI-066]] landed
mid-flight and conflicted in exactly one hunk (the `--dry-run` printout);
resolved keeping both changes, renumbered to nine steps.
