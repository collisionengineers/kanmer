## Outcome

The protected remote-public verifier accepts a descriptor that references bearer material through a local token file while continuing to reject inline secret values.

## Why

The verifier currently rejects its own documented `tokenFile` reference because its unsafe-key check treats the key name as an inline secret. That prevents the canonical public-tunnel proof from running.

## Verification

Run the focused remote-public-client tests and the canonical protected-environment verifier against a disposable authenticated tunnel. Preserve failed attempts and do not weaken safety assertions.
