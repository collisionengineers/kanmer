## What

`AGENTS.md`'s repo map (§ the `plugins/` tree, around line 149) says:

```
      .codex-plugin/plugin.json    # codex manifest  → ../.mcp.json
      .mcp.json           # codex companion ({"mcpServers":…} + ${PLUGIN_ROOT}) — must live at plugin root
```

Both lines are now wrong:

- The file `plugins/kanmer/.mcp.json` **does not exist** — [[MCP-016]] deleted it,
  because `agy` reads it at the plugin root regardless of any manifest and would
  otherwise keep advertising a server that cannot launch.
- `.codex-plugin/plugin.json` no longer has an `mcpServers` key at all, so it
  points at nothing.
- The `${PLUGIN_ROOT}` in the second line was **already** stale before that:
  [[MCP-011]] replaced that form with `"cwd": "."` and did not update the map.

## Why it is a separate ticket

MCP-016 worked under a standing instruction not to commit any `AGENTS.md`
change (the file carries a marker-delimited managed block that `kanmer-setup`
and Connect rewrite, so an incidental edit there is easy to get wrong and hard
to review). The correction was filed rather than absorbed.

## Approach

Edit only the hand-authored repo map, not the managed block. The two lines
become one:

```
      .codex-plugin/plugin.json    # codex manifest — SKILLS ONLY, no mcpServers (FRD-012 R6)
```

and `mcp/claude.mcp.json` stays described as the one MCP config the plugin
ships. Check `git diff AGENTS.md` shows nothing inside the managed markers, and
`npm run verify:agents-block` still passes (it compares the managed block, so a
repo-map edit must leave its 28 checks green).

## Verification

- [ ] The repo map names no `plugins/kanmer/.mcp.json`
- [ ] `npm run verify:agents-block` passes
- [ ] The diff touches nothing between the managed-block markers
