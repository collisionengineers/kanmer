## What

`scripts/release.mjs` ends by checking that `latest.yml` is fetchable. Make it
check the installer and the blockmap too, and fail the release if any expected
asset is missing.

## Why

**Three consecutive releases uploaded incompletely**, each time with
electron-builder logging a successful upload:

| Release | What was missing |
|---|---|
| 0.3.0 | `Kanmer-Setup-0.3.0.exe.blockmap` |
| 0.3.1 | `Kanmer-Setup-0.3.1.exe` **and** `latest.yml` |
| 0.3.2 | `latest.yml` |

Every one needed a manual re-publish. This is not a fluke — it is the normal
behaviour of this publish path and it must be assumed rather than hoped against.

The existing `latest.yml` check is the only reason none of these shipped broken,
and it caught only two of the three. **0.3.0 passed the gate while missing its
blockmap**, which is the quiet failure: `Provider.getBlockMapFiles` derives the
*previous* release's blockmap URL by string-substituting the version, so a
missing old blockmap silently costs every client on that version a full ~78 MB
download instead of a differential one. Nobody notices; everyone pays.

The 0.3.1 case is the loud one: `/releases/latest` pointed at a release whose
manifest 404'd. Every installed client would have failed its update check.

## Approach

- Extend the final verification to assert all three assets exist on the release,
  with plausible sizes — an `.exe` of a few hundred bytes is a failed upload
  that returned 200.
- Given a 3-for-3 failure rate, consider **re-publishing automatically** on a
  detected gap rather than only refusing, then re-verifying. A refusal after the
  tag has been pushed leaves `/releases/latest` broken until a human intervenes,
  which is exactly the state 0.3.1 was in.
- Worth checking whether `EP_GH_IGNORE_TIME=true` (needed for both manual
  re-publishes) should just be set by the script.
- Backfilling v0.3.0's blockmap is a separate question — it needs a rebuild of
  that version. Decide, don't drift.

## Outcome

Shipped in **PR [#45](https://github.com/collisionengineers/kanmer/pull/45)**,
squash-merged 2026-08-16 as `0c4ffda`.

`release.mjs` now verifies **every** published asset after publishing, not just
`latest.yml`: presence, `state == "uploaded"`, size against the local build, and
GitHub's `sha256` digest against a locally computed one — full integrity with
**zero bytes downloaded**, because the script is holding the files it just built.
The deciding logic is a new pure, dependency-free `scripts/verify-release-assets.mjs`.

Operator decisions, all implemented as given:

- A missing `.exe.blockmap` is a **hard failure** (with a test asserting the
  severity, so it cannot be quietly downgraded later).
- On a gap: re-publish **exactly once**, re-verify, then fail. Bounded, no loop.
- On a second failure: **refuse loudly, do not demote.** The refusal names
  `gh release edit v<v> --prerelease` as a suggestion rather than running it.
- `EP_GH_IGNORE_TIME` is set by the script — load-bearing, since without it the
  repair pass would itself silently no-op.
- **v0.3.0's blockmap is not backfilled** — accepted gap, recorded in the plan,
  `AGENTS.md` gotcha 12, the FRD-021 amendment, and `release.mjs`'s residual
  checklist so it cannot read as forgotten. Confirmed still missing during
  verification.

**The durable win:** the tests are `node:test` (`scripts/` is dependency-free, so
this needed no root devDependency, no root config and no `package-lock.json`
churn), wired as `test:scripts` into `npm test` — which is step 1 of the release
GATE and item 1 of `AGENTS.md` §10. The golden fixtures captured from the three
releases that actually failed now gate every future release.

**Shipped differently than planned:** one extra fix, found during review and in
scope. `refuse()` used `process.exit(1)`, which after a `fetch()` trips libuv on
Windows — the process dies with **127** and prints `Assertion failed:
!(handle->flags & UV_HANDLE_CLOSING)` directly under the refusal, so an operator
cannot tell a refusal from a crash. That would have landed on this ticket's most
important new path (the second-failure refusal) and also affected the
*pre-existing* refusal after the `/releases/latest` fetch. `refuse()` now sets
`process.exitCode` and throws a sentinel; all call sites unchanged.

**Follow-up filed: [[GUI-085]]** — `apps/gui/src/main/kanmerGit.test.ts` fails
non-deterministically on `main` (real `git` calls of 4.6–8.7 s against vitest's
5 s default `testTimeout`). Pre-existing, reproduced with this branch's changes
stashed; it matters because `npm test` is step 1 of the release gate.

Governing doc: `docs/functional/frd/FRD-021-auto-update.md` **R3** — met and
strengthened, requirement text unchanged, "Amended — GUI-066" as-built section
appended.
