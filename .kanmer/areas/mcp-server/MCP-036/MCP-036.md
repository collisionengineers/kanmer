## What
Resolve and validate the immutable Kanmer board/project context before `KanmerHttpHost.start()` binds its loopback listener, and roll back any partial startup on fingerprint/root failure.

## Why
MCP-025 checklist #62 and FRD-025 RA-PROJECT require one project to be resolved before binding. The current `start()` calls `httpServer.listen()` first and only then awaits `projectFingerprint()`, whose first operation resolves the root. With no board, a runtime probe reports `no Kanmer board found` after a listener was already bound; an embedded host can therefore fail startup with a live listener/resource leak. The host must not expose or bind until project/auth/config validation succeeds, and failed starts must clean up listeners/timers/sockets.

## Verification
- Add a regression that starts from a root-discovery failure and proves no listener/resource remains.
- Prove a valid start resolves one project/fingerprint before the listener is bound and readiness remains unchanged.
- Run HTTP unit tests, HTTP smoke, stdio/protocol/discovery smokes, build, typecheck, and diff checks.
