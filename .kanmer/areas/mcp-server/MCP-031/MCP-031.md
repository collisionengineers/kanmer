## What

Make the Streamable HTTP server factory session-safe. createKanmerMcpServer() currently assigns every server instance to module-global server; helper and handler closures read that global after registration. When a second HTTP session initializes, a request on the first session can use the second session's client identity/capability context (for example activity attribution and elicitation eligibility).

## Why

Stateful HTTP supports multiple concurrent sessions. Per-session connection state must not bleed across sessions, especially identity/audit and destructive-operation capability decisions.

## Verification

- Initialize two HTTP sessions with distinct clientInfo values.
- Invoke a mutation from the first after the second initializes and prove the activity actor remains the first client.
- Exercise a destructive/elicitation-capable handler to prove it reads the matching session capability context.
- Preserve stdio and the one canonical tool registry.

## Outcome


## 2026-08-23 archived audit

Disposition: resolved in current main. `packages/mcp-server/src/http.ts` stores a complete server/transport/principal capability context per session in `HttpMcpServer.sessions`; `smoke-http.mjs` initializes two sessions with distinct client identities/capabilities, mutates through Session A after Session B exists, and verifies Session A destructive behavior. The current HTTP rail passed 61/61. No unique unresolved defect remains.
