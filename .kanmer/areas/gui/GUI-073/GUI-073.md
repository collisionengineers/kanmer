## What

Connect shows **"Antigravity · register-only"**, which reads as "this host gets
less than the others". It does not — Antigravity has full project-level support.
The label means something narrower than it says.

## Why

The user is right, and the code says so. `providers.ts:374-388`:

```ts
id: "antigravity",
register: { kind: "configFile", configPath: ".agents/mcp_config.json", … },
install: { kind: "copySkills", skillsScope: "project", skillsDir: ".agents/skills" },
dispatch: false,
```

**Project-scoped MCP config and project-scoped skills** — written into the
project, exactly like the hosts that carry no warning. The in-repo comment even
notes `.agents/skills` is Antigravity's *primary* project location and is the
same tree opencode reads.

The only thing it lacks is **headless dispatch**, and the reason is recorded:
`agy -p` is known-broken piped (GH #318/#76).

But the badge is rendered from `dispatch` alone — `Settings.tsx:416`:

```tsx
{!p.dispatch && <span className="hint"> · register-only</span>}
```

So "cannot dispatch in the background" is being displayed as "register-only",
which in a panel headed *"Registers this project's board … and installs the
skills"* implies it does the first and not the second. It does both.

## Approach

- Say what is actually missing: something like "no background dispatch", not a
  term that reads as a capability tier.
- The flag is fine; the wording maps it to the wrong concept. Check whether
  `listProviders` should expose what a host *does* support (register / skills /
  dispatch) rather than a single boolean the UI has to interpret.
- While here: is `dispatch: false` still true? The comment is dated "v1" and
  cites upstream issues — worth a look before writing copy that outlives it.

## Verification

- [ ] Antigravity's row no longer implies reduced project support.
- [ ] Whatever replaces the label names the actual limitation, and matches
      whether the host appears in the "Dispatch to agent →" menu.
- [ ] Connecting Antigravity still writes `.agents/mcp_config.json` **and**
      `.agents/skills` — the capability the old label denied.
