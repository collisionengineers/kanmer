## What

`installSkills` (`apps/gui/src/main/connect.ts`) returns early for
`kind: "marketplace"` hosts, **before** `ensureAgentsBlock(root)`:

```ts
if (provider.install.kind === "marketplace") {
  … marketplaceCommands …
  return notes.join("; ");           // ← returns here
}
// copySkills: always ensure the AGENTS.md block; copy skills for a project dir.
await ensureAgentsBlock(root);
```

So connecting **Claude Code** or **codex** — and only those two, the marketplace
hosts — never writes or refreshes the managed AGENTS.md block. grok, opencode and
Antigravity get it.

## Why it matters

FRD-012 **R3** states the opposite as a requirement: *"The **AGENTS.md managed
block** is written for **every** provider — the universal orientation layer
(ADR-0009), no longer anyone's sole delivery."* ADR-0009's contract hierarchy puts
that block at level (3) precisely because it is *always in context*, unlike
skills, which are on-demand and permission-gated. A Claude-only or codex-only
project therefore loses the one layer the ADR says cannot be skipped, and it loses
it silently — the connect output for those hosts says "plugin installed" and
nothing about the block.

Either the code is wrong (most likely — R3 and ADR-0009 both argue for
universality, and the block is cheap and idempotent) or R3 is. One of them must
move; today a reader of FRD-012 is misinformed about what Connect does.

Note the block *is* removed symmetrically on disconnect only for hosts that were
given it, so the asymmetry is confined to install.

## How it was found

[[GUI-073]], while rewriting the Connect panel blurb, drafted the sentence "Every
host also gets the AGENTS.md block" from FRD-012 R3 and then checked it against
`connect.ts` before shipping it (ADR-0009's method clause — establish it, don't
infer it). The claim was false, the blurb was rewritten to a true one, and this
ticket carries the divergence. **Not fixed in GUI-073**, whose scope was only
what Kanmer *says* about Antigravity.

## Approach

- Decide which side is right — the code or R3 — and say so in the ticket before
  changing either.
- If the code: hoist `ensureAgentsBlock(root)` above the marketplace branch, and
  add the "AGENTS.md block ensured" note to the marketplace output so the user can
  see it happened. Check the disconnect side stays symmetric.
- Cover it with a test: connecting a marketplace host leaves the managed block
  present and idempotent on a second connect.

## Verification

- [ ] Connecting Claude Code (or codex) in a project with no AGENTS.md leaves the
      managed block present, and a second connect is a byte-identical no-op.
- [ ] Whichever of code / FRD-012 R3 was wrong is corrected, and the other cited.
- [ ] Disconnect behaviour for marketplace hosts is stated and tested, not left
      implicit.
