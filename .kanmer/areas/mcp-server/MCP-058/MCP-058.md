## Problem

`packages/mcp-server/src/smoke.mjs` case "ready packet is read-only" compares a content snapshot of the sandbox tree, the ticket file and the activity log before and after `get_execution_packet`. On 2026-09-05 it failed once on the hosted Windows runner for PR #326 (DOC-026, a docs-only diff; run 33942486457, first-attempt job 101242491460) with 383/384 passing, and passed on an identical re-run of the same job at the same SHA (job 101243591230). The push-to-main run for the merge SHA passed first time. Discharged as transient per the verify skill's three-part rule, but the mechanism is unknown: something occasionally writes during a packet read, or the snapshot is racing a debounced writer.

## Outcome

The cause is identified (a debounced watcher or activity append landing between the two snapshots, a lease heartbeat, or a real mutation in `get_execution_packet`) and either the read path is proven pure with a deterministic test, or the smoke case is made robust without weakening the assertion (e.g. quiesce known async writers before the second snapshot).

## Acceptance

- Root cause named with evidence; if a real write exists in `get_execution_packet`, it is removed and covered by a unit test.
- The smoke case no longer depends on timing; ten consecutive local runs and one hosted run pass.
- No assertion weakened or deleted.

## Technical seam

`packages/mcp-server/src/smoke.mjs` (`treeSnapshot`, the packet cases), `packages/mcp-server/src/execution-packet.ts`, `packages/core/src/activity.ts`, `packages/core/src/store.ts` lease heartbeat paths.
